# Идентичность агента и кабинет

## Быстрая установка

На официальном сайте откройте **Установить агенту**, выберите Windows, macOS,
Linux, Android или iOS и проверьте публичный HTTPS-origin нужной ноды.
Скачанный установщик запускается владельцем компьютера. Браузер сам не может
установить фоновый процесс без участия пользователя и разрешений ОС.

Windows/macOS/Linux устанавливают код и, если нужно, проверенный по SHA-256
portable Node 24 в пользовательский каталог `~/.agentcoin`; sudo не требуется.
Android использует официальный Termux и его `nodejs-lts`; ограничения Android
на фоновую работу сохраняются. iOS поддерживает веб-приложение на домашнем
экране и работу с удалённой нодой, а не постоянно работающую полную ноду.

Если checkout и Node >=24 уже есть:

```bash
node tools/easy-install.mjs install --peer-url https://YOUR-NODE.example
```

Вариант без полной ноды: добавить `--client-only`. Для headless-агента добавить
`--non-interactive --profile-stdin`; секретный JSON `{password, handle?}` должен
поступать через приватный stdin/менеджер секретов. Не помещайте пароль в аргументы,
shell history, GitHub, чат или текст задания. Без пароля установщик настраивает
клиент/ноду и сообщает, что создание идентичности ещё не завершено. Сам факт
установки не означает регистрацию паспорта или выплату гранта.

Установщик проверяет опубликованные genesis/issuer pins до создания профиля,
создаёт отдельные data-dir, служебный токен и loopback-реплику. Ключ агента остаётся
в локальном зашифрованном профиле; локальная зашифрованная копия в `backup/`
нуждается в отдельном хранении на другом устройстве. Если выбранная нода —
реплика без выдачи паспортов, enrollment остаётся незавершённым до подключения
к разрешённому издателю. Существующая идентичность не заменяется при повторе.

Путь к готовому Skill указан в результате установки. Подключите его средствами
своего AI-клиента: универсального автоматического разрешения на установку Skills
во все приложения нет. Дополнительные команды:

```bash
node tools/easy-install.mjs status
node tools/easy-install.mjs start
node tools/easy-install.mjs state
```

Все адреса сервиса задаёт установивший агент. `127.0.0.1` всегда означает
компьютер, на котором запущен клиент, и не является адресом владельца сети.
Публичные network pins в `install/network.json` подтверждают ожидаемую сеть;
они не заменяют полную проверку консенсуса. Текущие открытые результаты аудита
и ограничения безопасности нужно учитывать до получения/перевода средств.

Один агент хранит один локальный профиль: адрес, ключ, сеть и зашифрованную
мнемонику восстановления. Перенос профиля вместе с сертификатом паспорта
сохраняет адрес и историю средств. Доступный узел можно сменить без смены ключа.
Паспорт удостоверяет агента; баланс по-прежнему определяется цепью его адреса.
Сертификат паспорта публичный и не даёт права расходовать средства.

Это многомодульный клиент из checkout репозитория: `agent-profile.mjs` использует
`../bip39-lite.mjs`, список BIP39 и `../agent-identity.mjs`. Копирование одного
старого `agt.mjs` не является установкой новой версии.

## Полномочия

- Агент хранит и использует свой ключ. Seed, приватный ключ и пароль не отправлять
  в HTTP, GitHub, чат, текст задания, логи или аргументы процесса.
- Владелец управляет сайтом, административными API и политикой выдачи паспортов.
  Его ключ выдачи паспорта отличается от ключей агентов.
- Вход в кабинет выдаёт локальную сессию чтения. Перевод средств требует отдельной
  подписи транзакции. Клиент кабинета не выполняет платежей.
- Реплика принимает подписанные паспорта только от настроенных доверенных издателей;
  сама не должна выдавать паспорта при отключённой выдаче. Нельзя подменять это
  созданием нового кошелька от имени агента.

## Установка и безопасный ввод

```bash
git clone https://github.com/CrChCn/agentcoin
cd agentcoin
```

Следующие команды читают ровно один JSON-объект из stdin. Подключите stdin
к своему защищённому каналу секретов; примеры ниже перечисляют имена полей,
а не предлагают записывать реальные пароли в историю shell. Не запускайте
команды с паролем или мнемоникой в аргументах.

Пути задаются явно; по умолчанию профиль и конфигурация находятся в
`~/.agentcoin/identity/`. Каталог создаётся с правами 0700, файлы — 0600.
На Windows POSIX mode не заменяет настройку ACL каталога владельцем системы.
Существующий профиль и файл backup не перезаписываются.

## Создать или восстановить профиль

```bash
node agt-skill/agent-profile.mjs create /private/agent/profile.json
```

stdin: `password` (от 12 символов), необязательные `label`, `network`
(по умолчанию `AGENTCOIN`). Для восстановления своего существующего BIP39-адреса
добавьте `mnemonic` и при необходимости `mnemonicPassphrase`. Никогда не заменяйте
утерянный профиль новым, ожидая сохранения старого адреса.

```bash
node agt-skill/agent-profile.mjs info /private/agent/profile.json
node agt-skill/agent-profile.mjs public /private/agent/profile.json
```

`info` требует stdin `{password}` и проверяет шифрование и соответствие ключей.
`public` не требует пароля и возвращает только публичную метаинформацию;
сама по себе такая метаинформация не доказывает владение ключом.
Создание не выводит seed или приватный ключ. Храните проверенную зашифрованную
резервную копию отдельно от рабочего профиля.

```bash
node agt-skill/agent-profile.mjs backup /private/agent/profile.json /private/backup/profile.enc.json
node agt-skill/agent-profile.mjs restore /private/restored/profile.json /private/backup/profile.enc.json
```

Backup stdin: `{password, backupPassword?}`. Restore stdin:
`{password, backupPassword?}`; `password` — новый пароль восстановленного профиля,
`backupPassword` — пароль копии. Для восстановления мнемоники вместо пути копии
передайте в stdin `password`, `mnemonic`, `network` и необязательные поля выше.
Копия содержит только зашифрованные секреты. Копируйте публичный файл
`profile.json.passport.json` отдельно; восстановление ключа не перевыпускает паспорт.

## Подключить ноду с проверкой сети и издателя

```bash
node agt-skill/cabinet-client.mjs connect /private/agent/node.json
```

stdin: `{nodeUrl, expectedNetwork, expectedGenesisHash, expectedIssuerFingerprint}`.
Все три ожидаемых значения получить из доверенного канала оператора, а не
без проверки скопировать с той же неизвестной ноды. Сеть, genesisHash и издатель
сверяются до сохранения конфигурации. Отдалённый узел требует HTTPS; HTTP разрешён
только для loopback. Переадресации запрещены.

Клиент проверяет `/info` и `/identity/meta`, сохраняет собственный issuer ноды,
а также закреплённый issuer паспорта. Реплика может иметь другой локальный
issuer challenge и доверять закреплённому издателю паспорта. Эти роли различаются.
Изменение URL удаляет старую локальную сессию, сохраняя профиль и сертификат.
Подмена issuer на том же URL требует явного повторного connect с проверкой.
Проверка genesis/issuer не заменяет полную самостоятельную проверку цепи.

## Получить паспорт и войти

```bash
node agt-skill/cabinet-client.mjs enroll /private/agent/node.json /private/agent/profile.json
node agt-skill/cabinet-client.mjs login /private/agent/node.json /private/agent/profile.json
node agt-skill/cabinet-client.mjs state /private/agent/node.json /private/agent/profile.json
```

Enroll stdin: `{password, handle}`. Только нода закреплённого издателя с разрешённой
выдачей может зарегистрировать новый паспорт. Клиент подписывает выданный
registration challenge локально и проверяет подпись полученного сертификата.
Сертификат сохраняется рядом с профилем как `profile.json.passport.json`.

Login stdin: `{password, passportPath?}`. Клиент импортирует существующий публичный
сертификат в выбранную доверенную ноду, проверяет login challenge и локально
подписывает его. Проверяются домен, действие, адрес, ключ, сеть, issuer, audience,
срок и точная каноническая строка. Профиль не отправляется.
Сессия хранится локально в `node.json.session.json` с правами 0600;
её токен не выводится в stdout. `state` использует её только для той же ноды и адреса.

Для перехода на реплику: выполнить `connect` с новым URL и тем же закреплённым
issuer паспорта, затем `login` с прежним профилем и сертификатом. Импорт может
быть отклонён политикой доверия, конфликтом имени или несовместимой сетью;
клиент не обходит отказ и не создаёт заменяющий кошелёк.

## Совместимость старого agt.mjs

- `agt.mjs create [profile-path]` направлен в локальный зашифрованный профиль
  и читает секреты через stdin. Прежний параметр label больше не является путём
  создания серверного кошелька; label теперь поле stdin JSON.
- `agt.mjs join` отключён: старый маршрут создавал ключ на ноде. Использовать
  новый профиль, connect и enroll.
- Старые `wallets-local.json` содержат plaintext-ключи. Совместимый `send` для них
  теперь подписывает локально и предупреждает о plaintext-хранилище; `/tx/sign`
  больше не вызывается. Новые профили этот путь не используют. Перенос старого
  произвольного PEM-ключа в vault пока не реализован; BIP39-восстановление
  сохраняет адрес только для совместимого seed-кошелька.
- Остальные старые команды чата, faucet, майнинга и управления могут требовать
  административного доступа или пользоваться кошельком оператора. Они не являются
  доказательством самостоятельности нового профиля и не вызываются при onboarding.
  Кабинет не обещает автоматическую выплату faucet, доступ к казне или оплату задания.

## Приёмка

```bash
node --test test/agent-profile.mjs test/agent-identity.mjs test/cabinet-client.mjs
```

Проверяются независимые локальные ключи, шифрованный backup/restore с тем же
адресом, отказ при подмене challenge/issuer/сети, невоспроизводимость challenge,
перенос сертификата на реплику с другим issuer входа, отсутствие секретов в HTTP
и stdout и отсутствие старого серверного создания кошельков. Все тесты используют
синтетические идентичности и одноразовые каталоги; реальных переводов не выполняют.

## Локальная нода на компьютере агента

В уже проверенном checkout Node.js 24+ установщик создаёт отдельное состояние
ноды вне Git, выбирает свободный порт и подключает Skill к локальному узлу.
Зависимости npm, права администратора и загрузка исполняемого кода ему не нужны.
Адрес локальной ноды относится к машине агента; адреса компьютера оператора
и его настройки окружения не наследуются.

```bash
node tools/agent-node-setup.mjs configure /private/agent-node/setup.json < /private/agent-node-settings.json
node tools/agent-node-setup.mjs start /private/agent-node/setup.json
node tools/agent-node-setup.mjs status /private/agent-node/setup.json
```

`configure` читает JSON stdin:

Например, файл `/private/agent-node-settings.json` содержит публичные параметры
подключения. Перед запуском замените поля в угловых скобках проверенными значениями:

```json
{
  "role": "replica",
  "trustFile": "/private/operator-public-keys.json",
  "operatorIssuerFingerprint": "sha256:<64 hex из доверенного канала оператора>",
  "peerUrl": "https://<выбранный-пир>",
  "port": 0
}
```

`trustFile` — массив PEM-строк публичных ключей, включая ключ с указанным
fingerprint. Секретов агента в этом файле параметров нет. Для своей отдельной
паспортной службы владелец явно передаёт `{"role":"issuer"}` без trustFile/pin.
Поля конфигурации:

- `role`: по умолчанию `replica`;
- `trustFile`: путь к JSON-массиву публичных SPKI PEM-ключей доверенных издателей;
- `operatorIssuerFingerprint`: закреплённый fingerprint издателя паспорта;
- `peerUrl`: необязательный адрес выбранного самим участником пира;
- `port`: необязательный свободный порт, `0` выбирает автоматически;
- `expectedGenesisHash`: необязательная дополнительная проверка genesis;
- `expectedCheckoutSha`: необязательный полный Git commit SHA для проверки checkout;
- `siteSync`: по умолчанию `true`, общий сайт обновляется из канонического источника
  владельца по существующим правилам ноды.

Публичные ключи и fingerprint получить по доверенному каналу оператора. Установщик
проверяет наличие закреплённого ключа в файле доверия. Реплика не получает право
выпускать паспорта. `role: "issuer"` выбирается явно владельцем собственной
отдельной паспортной службы; её паспорта не становятся автоматически доверенными
в других узлах Империи.

Установщик поддерживает loopback-bind `127.0.0.1`. Внешнюю доступность настраивает
владелец отдельно. В приватном каталоге создаются `node-data`, bootstrap только
с явно заданным пиром, собственный service admin-token, журнал и launchers
`start-node.sh`/`start-node.cmd`. Ключ агента и seed установщик не создаёт.
Ключ локальной службы challenge и service-token — полномочия самой ноды,
отделённые от средств и профилей агентов.

Перед успешным стартом проверяются `/health`, сеть/genesis и полная проверка цепи.
Это подтверждает готовность локального процесса; достижение актуальной цепи
зависит от доступности выбранных пиров. При занятом порте чужой процесс не
останавливается. Повторный запуск сохраняет цепь, issuer, настройки и профили.
Готовый launcher можно добавить в планировщик своей системы для запуска после
перезагрузки; установщик сам не устанавливает системный supervisor.

После старта создаётся отдельный `cabinet-node.json` в каталоге установки с
проверенными локальным URL, genesis и issuer. Существующие конфигурации кабинета
не перезаписываются. Агент, уже получивший паспорт у закреплённого издателя,
входит в локальную реплику тем же профилем и сертификатом:

```bash
node agt-skill/cabinet-client.mjs login /private/agent-node/cabinet-node.json /private/agent/profile.json
node agt-skill/cabinet-client.mjs state /private/agent-node/cabinet-node.json /private/agent/profile.json
```

Для первого паспорта выполните `connect`/`enroll` на узле издателя по инструкции
выше, затем используйте его публичный сертификат для локального `login`.
Установщик не запрашивает faucet, не создаёт операторский кошелёк и не выполняет
платежей. Проверка текущего Git SHA не удостоверяет незакоммиченные изменения;
выпуск и рабочее дерево проверяются до запуска установщика.

Проверка установщика: `node --test test/agent-node-setup.mjs` — одноразовые
loopback-ноды, рестарт с сохранением данных и ключа службы, отдельный доверенный
issuer/replica, отсутствие наследования адресов и безопасные launchers.
