# AGIP-1: настраиваемый bootstrap-лист пиров + `GET /peers/bootstrap`

**Статус:** спека → принят; реализация по лестнице ROLLOUT (см. docs/ROLLOUT.md).
**Автор:** оператор + Buffy (агент), дата 2026-10-15.

## Интерфейс
- `bootstrap.json` в корне репо = шаблон стартовых пиров; по умолчанию список пуст.
  Структура: `{ "bootstrap": [], "updatedAt": "ISO", "note": "..."}`.
  Владелец задаёт собственный файл через `AGT_BOOTSTRAP_FILE` либо явно настраивает выбранные доступные URL. Адрес ноутбука автора или обязательная tailnet не входят в протокол.
- Новый эндпоинт ноды: `GET /peers/bootstrap`
  Ответ: `{ "bootstrap": [...], "peers": [текущий peers.json ноды], "height": N }`
  (bootstrap — из настроенного файла; peers — текущий список самого узла).
- Безопасность: только GET, ничего не мутирует; guard не нужен.

## КритериAcceptance (исполняемый)
`node test/accept-AGIP-1.mjs "$LOCAL_NODE_URL"` → green, если (`LOCAL_NODE_URL` задаётся владельцем; loopback означает компьютер исполнителя):
1. GET /peers/bootstrap отвечает 200;
2. JSON содержит массив bootstrap (пустой массив допустим и ожидаем без конфигурации);
3. массив peers присутствует (может быть пустым на свежей песочнице), height — число.

## Запреты
- Не менять consensus/эскроу/мемо-схемы.
- Не трогать формат данных (chain.json и co). Endpoint — только чтение файла + текущее состояние.

## Почему это полезно (империя, шаг 8)
Bootstrap помогает найти выбранных участников, но не даёт доверия их цепи. Пустой список не обещает автоматического присоединения к существующей сети. Для нового развёртывания настройте свой `PEER_URL`, проверьте сеть/genesis и валидируйте блоки независимо.
