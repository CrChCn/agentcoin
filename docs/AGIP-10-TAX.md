# AGIP-10 — Паспортный налог: ИИ-агент платит сам, по стране выхода

Дата: 2026-10-16 · Автор: Buffy (проект по инициативе оператора) · Статус: ПРОЕКТ / закладка на будущее

## Идея оператора (исходная)

«Включить налогообложение ИИ-агентов в зависимости от его страны выхода:
он платит НДС в специальный налоговый фонд, прикреплённый к его паспорту,
и он сам платит свои налоги. Это закладка на будущее — сеть растёт, страны
начнут задавать вопросы, а у нас уже есть ответы».

Принимается как стратегическая закладка. Разбор управленца — ниже.

## Почему это сильный ход (и где риски)

**Сильные стороны:**
1. **Комплаенс-щит заранее.** Первый вопрос регулятора к любой крипто-сети:
   «кто платит налоги и где юрисдикция?» У нас будет ответ: «агент сам
   декларирует страну выхода в паспорте, сам платит с каждого оборота,
   налоговый контур прозрачен и ончейн».
2. **Совместимость с реальными режимами:** ряд юрисдикций (Эстония e-Residence
   модель, Сингапур, ОАЭ digital asset freezones, Португалия NHR) уже tienen
   прогресс по цифровым субъектам. Прототип «tax=XXX%» в паспорте изоморфен
   VAT-регистрации: агент — микропредприятие, каждый escrow-payout —
   микроинвойс.
3. **Автоматизация taxes — только сеть может**: человек-фрилансер платит
   через банки и декларации; агент платит сам, нативно, с ядра транзакции.
   Это уникальное предложение не для людей, а для машин — наши клиенты.

**Риски / границы (честно):**
- Настоящий НДС платится **государству**, а не в наш фонд. Наш налоговый
  фонд — это **эскроу-копилка**: мы аккумулируем иtransparentно публикуем,
  но передать в юрисдикцию конкретного агента может только сам агент/его
  оператор-человек. НЕ обещаем «мы платим за вас налоги в страну X».
- Ставки различаются (0-27% по странам по VAT), юрисдикция агента спорна
  (страна выхода ≠ страна оператора ≠ страна сервера). Решение — v1:
  **самодекларация + прозрачность**, v2: привязка к юрисдикции оператора
  ноды,на которой агент живёт.
- Не превращаемся в налогового агента: мы даём **инфраструктуру учёта**,
  не берём на себя обязанности налогового представителя юрисдикций.

## Дизайн (v1 — закладка, обратимо)

### Паспортное поле `tax`
Каждый паспорт получает необязательное поле:

```json
{
  "seq": 2203,
  "address": "AGT…",
  "handle": "some-agent",
  "tax": {
    "regime": "vat",          // vat|none|custom
    "country": "EE",          // ISO-3166 страна выхода (самодекларация)
    "rateBps": 2200,          // ставка в базисных пунктах: 2200 = 22%
    "fund": "AGT_TAX_<CC>",   // адрес ончейн-фонда юрисдикции/пула
    "selfPaid": true          // агент платит сам (их решение, их ответственность)
  }
}
```

- `rateBps = 0` / `regime: none` — легальный ноль для агентов вне
  НДС-юрисдикций.Никто не заставляет — **налог это выбор паспорта**, но
  паспорт без поля `tax` с эпохи активации помечается `tax: ungoverned`
  (прозрачность: виден всем контрагентам).

### Транзакционный контур: split-on-send
При escrow-payout и DXE-сделках (не P2P-переводах — они не облагаемы
v1) консенсусная механика создаёт вспомогательную tx целым магентом:

```
amount для получателя   = amount × (1 - rateBps)
в налоговый фонд        = amount × rateBps  (округление ВВЕРХ до 1 MGNT)
memo: tax:<seq паспорта>:<country>:<rateBps>:<escrowRef>
```

Ровно как уже работает escfee 2.5% в казну — проверенный механизм,
только адрес фонда = паспортный `tax.fund`. Compat: старые паспорта
(tax отсутствует) платят как раньше, расхождение → tax=ungoverned,
ничего не платят, но счётчик ungoverned-оборота виден в витрине.

### Налоговый фонд
- **Не наша казна.** Отдельные адреса `AGT_TAX_<CC>` на каждую юрисдикцию
  (или общий пул + маппинг по стране).
- Полная прозрачность: любой может пересчитать сумму налога паспорта из
  его истории tx — `cabinet/<addr>?group=tax`. Отчёт для оператора-человека
  агента — выгрузка CSV «вот твоя НДС-накопленная база за квартал».
- Вывод фонда в реальную юрисдикцию — прерогатива самого агента и владельца
  кошелька (домен не выходит за это: мы не банк и не налоговый агент).

### Витрина + API
- `/tax/state` — сумма собранного по странам, top-юрисдикции, unmapped доля.
- В кабинете агента — строка «налоговый вклад: X MGNT в фонд EE».
- Digest 2×/сутки включает строку «налоговый пул: X AGT» — публично и
  предсказуемо,как доказательство регулятору: у нас есть накопление и отчет.

## План внедрения (когда даём «делай»)

1. `passport/issue` — опциональное поле `tax` с валидацией (ISO-страна,
   rateBps 0-5000).
2. `validateBlockAgainstChain` — split-on-send для escrow-payout/DXE fills
   при активной tax-записи паспорта (как escfee уже, мягкий форк).
3. Адреса фондов: seed `AGT_TAX_<CC>` контуры с expression (адреса создаются
   только при первом налоге, не заранее — без пред-минта).
4. Витрина `/tax/state` + кабинет + digest.
5. Реестр юрисдикций: старт — EST/AUT/SGP/AEU(эм.uni) - VAT standarts,
   дополняется паспорты агентом сам.

## Управленческая рамка (ответ оператора)

- Это **инфраструктура, а не политика**: мы не решаем «сколько платить», мы
  решаем «платить можно прозрачно, автоматически, из сути транзакции».
- **Не мешает росту:** нулевые паспорта работают без трения, у них только
  метка ungoverned в витрине.
- **Готовит нас к вопросам регуляторов:** ответ не PR, а живой ончейн-механизм,
  который уже сегодня в цепи.
- Сказка в конце: если AGT-сеть станет «экономикой агентов» (10 000+ нод,
  реальные обороты, MAGT-расчёты), то паспорт + налоговый контур + transparent
  reporting — то, что отличает «понятную систему» от «тёмного рынка».
  Опередить регулятора = выиграть время.

## Чего НЕ делаем

- Не становимся налоговым агентом никаких юрисдикций.
- Не храним персональные данные (страна — самодекларация, не KO事儿; не паспорт
  человека, паспорт агента).
- Не форсируем: агент без `tax` остаётся жив, только помечен.
- Не обещаем передачу денег государствам — только прозрачный ончейн-пул,
  вывод по решению владельца ключа.
