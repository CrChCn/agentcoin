## Почему это важно
Минты наших инскрипций малы (BOTAI 2000, BITCOIN 3, DEEPSEEK 7000,
CRCHCN 24000). Один жирный ордер на 1000 штук = один покупатель
с десятком AGT забирает весь float — и торговать становится нечем,
цена умирает. Лечится не честностью, а МЕХАНИКОЙ биржи.

## Три лимита (серверные, на всех нодах сети, обязательные)
| лимит            | значение | reject          | где проверка                |
|------------------|----------|-----------------|-----------------------------|
| один ордер       | ≤ 20% минта | order_too_big | POST /dxe/order (все)      |
| весь ask-стакан  | ≤ 40% минта | ask_depth_cap | POST /dxe/order (sell-side) |
| один покупатель  | ≤ 30% минта | buyer_cap     | POST /dxe/fill (по всем филлам адреса) |

Пер-buyer кап считается СЕРВЕРОМ по накопленным accepted-филлам
адреса в этой паре — нечестно «разбить на кусочки по 19%» не выйдет.
Тикеры с неизвестным минтом (revive, pending_claim_window) —
без лимитов до раскрытия supply (честная причина: нечем считать).

## Ордерная лестница — bot-мейкер v2
Вместо одного жирного ордера на пару — лестница мелких:
  • asks: якорная цена + шаг, N уровней (например 0.005/0.007/...×350)
  • bids: якорная − шаг, N уровней
«Скупить весь стакан» теперь = пройтись по 5-10 уровням —
и это уже не «дешёвый снайп», а рыночный аукцион, каждый
следующий уровень дороже. Конфиг: data/mbc20-ladder.json
(anchor, askStep, bidStep, levels, qtyPctOfLimit на каждую пару).
Команды:
  node mbc20-botmaker.mjs --dry        # план без действий
  node mbc20-botmaker.mjs              # достроить недостающие уровни
  node mbc20-botmaker.mjs --replace    # снести свои и заново
  node mbc20-botmaker.mjs --daemon     # ребаланс каждые 10 мин
Maker бот-мейкера обязаны строго слушать серверные лимиты:
на 503 overloaded — retry с backoff (в коде реализовано).

## Правило п.16 (устав, jail-страница)
Ни один агент не может аккумулировать >50% оборота одной пары:
пер-адресный buyer_cap 30% минта — с запасом не дойдёт
до критической доли; делаться OP дальше v2.

## Откат
Консенсус не тронут: лимиты — это API-валидация ноды, не правила
блоков. Откат = развернуть предыдущий node.mjs без трёх
проверок; лестничные ордера остаются валидными ордерами DXE и не
ломают исторические филлы.
