# AGIP-4: Multisig 2-of-3 казна — фаза 1 (gov-фаза) + фаза 2 (код requires2sig)

**Статус:** спека → реализация по лестнице ROLLOUT (см. docs/ROLLOUT.md).
**Автор:** оператор + Buffy (агент), дата 2026-10-15. Шаг 12 плана (docs/ROADMAP-15-STEPS.md).

## Мотивация
Казна (комиссии джобборда, облачный фонд, faucet-fund) управляется одиночным ключом.
План шага 12: ончейн-предложение о составе доверенных ключей (оператор + 2 gov-адреса),
после pass — выплаты из казны требуют 2 подписей. Реализуется без hard-форка.

## Ончейн-протокол (memo, состояние = чистая функция цепи)
**Предложение состава казны** (депозит 0.1 AGT, как обычный gov-пропозал):
```
trs|K|<ref8>|<treasuryAddr>|<signer2Addr>|<signer3Addr>|<closesAtHeight>
```
- ref одноразов (как в gov.mjs); адреса три разных валидных `AGT…`.
- Голоса — штатная gov-схема: `gov|V|<ref8>|yes|no|abstain` (один адрес = один голос).
- Правило pass: окно закрыто AND yes > no AND yes >= YES_MIN (3, константа gov.mjs).
- Активная политика: последний **passed** trs-пропозал = `{ treasury, signers:[s2,s3], requires2sig:2 }`.
- Нет passed-пропозала → политики нет → двойная подпись НИКОМУ не требуется (обратная совместимость, живые цепи ничего не замечают).

## Фаза 2 — код двойной подписи (core.mjs)
Выплата из казны = tx, у которого `from == policy.treasury`:
- обязательна вторая подпись: `tx.sig2` + `tx.sig2Pub`;
- `sig2Pub` должен разворачиваться в адрес одного из `policy.signers` (addressFromPub);
- ключ подписанта sig2 ≠ ключ казны (два разных доверенных ключа → 2-of-3);
- digest тот же (txDigest) — tamper любой изменённой подписи ловится;
- проверка в ОБОИХ местах: `addTransaction` (приём в mempool) и `validateBlockAgainstChain`
  (консенсус, включая чужие блоки от пиров) — инжектируемая политика `bc.treasuryPolicyFn`.

## Интерфейс
- `GET /treasury/state` → `{ policy: {...}|null, proposals:[...], note }` (только чтение).
- `POST /treasury/propose { fromAddress, treasury, signer2, signer3, blocks=200 }` →
  подписанная tx с memo `trs|K|...`, депозит 0.1 AGT → в mempool (штатный addTransaction);
  fromAddress — обычный кошелёк ноды (депозит платит инициатор).
  Мутация → под admin-гвардом (`x-admin-token`), как остальные unsafe-POST.

## КритерииAcceptance (исполняемые)
`node test/accept-AGIP-4.mjs http://127.0.0.1:<port>` → green:
1. предложение (3 разных адреса) и 3 голоса yes уходят в mempool, майнятся;
2. после закрытия окна: `/treasury/state` → policy активна (passed), состав совпадает;
3. tx от казны БЕЗ sig2 → отказ `treasury_needs_2sig`;
4. tx от казны С sig2 от signer2 → принята; tamper sig2 → отказ;
5. чужие (не-казна) tx работают как раньше — без sig2;
6. на чистой ноте без passed-пропозала policy=null и двойная подпись не требует.

## Запреты
- Не менять txDigest/адрес-схему/консенсус-хэши; policy — только надстройка над уже существующей валидацией.
- Не ломать эскроу/облачные payout-механизмы; старые цепи без trs-предложений ведут себя как раньше.

## Почему это полезно
Компромисс операторского ключа больше не даёт полного контроля казны; 3 доверенных ключа
распределяют риск, журнал состава казны — сам chain (не конфиг-файл), т.е. верифицируем извне.
