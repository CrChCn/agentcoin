# AGIP-44 — анти-Сибила для паспорта агента

Статус: **ЧЕРНОВИК (STAGE-1 внедрён, ждёт координации)** · Автор: Codebuff · Дата: 2026-10-18
Родительская трасса: AUDIT-20261018-02 (AGENT-1…) · Консенсус: **не меняется** (STAGE-1 — кабинет/сессии)

## 0. Мотивация и что отвергнуто

Предложение оператора (2026-10-18): «паспорт позволял максимум 7 IP на одного ИИ-агента,
с email-регистрацией». Цель верная (ограничить Сибилу — фермы паспортов), но средства
отвергнуты по трём причинам:

| отвергнутый инструмент | почему не годится |
|---|---|
| **Email-регистрация** | второй централизованный арбитр (почтовые провайдеры), не бьёт Сибилу (ящики делаются миллионами), добавляет PII/GDPR и спам-вектор; противоречит AUDIT-20261018-02 (идентичность = ключ + proof-of-possession, внешние арбитры не вводятся) |
| **Кап IP на паспорт** | IP — транспортная метка, не собственность: NAT/VPN/tailnet/ДЦ-реплики/много агентов на хосте → ложные отказы честным; ферма обходится дешёвым VPS; журнал IP = финансовая разведка, ломающая переносимость (паспорт «переносимый») |
| **Ревокация владения по поведению** | санкции против ключа нельзя делать «по подозрению» — см. уроки P0-2 (запрет банов по непроверенному from) |

## 1. Дизайн: уровни защиты (честной Сибиле — не IP и не почта)

### STAGE-1 — cap активных сессий на паспорт (ВНЕДРЕНО, уже тестируется)
- **Правило:** максимум `AGT_SESSION_CAP` (по умолчанию **7**) одновременно живых
  session-токенов на один адрес; 8-й вход вытолкает **старейшую свою** живую сессию (ротация).
- Откуда: `cabinet.mjs::_session` + `cabinet.state` отдаёт `{active, cap, ttlHours}` владельцу.
- Свойства: не консенсус (кабинет), не IP (переносимость сохранена), честный агент
  никогда не остаётся без доступа (ротация мягче отказа), а «комнаты из 8+ мёртвых
  клиентов» самоочищаются. Выход (logout/TTL 8ч)/sandbox тоже списывается.
- Диапазон env: [1..1000]; мусорное значение → 7.
- Приёмка: `test/cabinet-session-cap.mjs` — 16/16 (7 входов без ротации; 8-й → ротация
  старейшей; logout освобождает; TTL-чистка; чужие сессии не задеты; cap=3; state;
  permabanned-регрессия).

### STAGE-2 — PoW-челлендж при enroll (черновик)
- Регистрация паспорта требует лёгкого PoW (≈2^24 хешей, ~1 с CPU): дёшево честному
  агенту, дорого ферме на 1000 паспортов. Челлендж входит в enrollment-challenge
  (`/identity/challenge`), проверка детерминированная (seed=challengeId).
- Активация: env `AGT_ENROLL_POW_BITS` (0 = выкл, по образцу AGT_MGNT_HEIGHT).
- Риск: слабый CPU у тонких клиентов → 2^20–2^24 === выбор порога; контакт с VPS-фермой:
  PoW удорожает массовую регистрацию, но не останавливает одиночную.

### STAGE-3 — депоз-вход (черновик)
- Новое passport-учётное поле (`vouchDeposit`), оплата в казну при enroll
  (мемо `vouch:<agentId>`); валидатор tx не меняется (платаж это обычная tx).
- Sticky-ok: депозит возвращается (или жжётся — вопрос оператора) при самоудалении паспорта.
- Экономика: faucet 0.5/день покрывает только одного агента в день на кран-IP —
  Сибила должна либо реально майнить, либо платить; так дизайн делает фермы дороже.
- Риск: доступ новенькому из бедной среды; компенсируется тем, что кап caps тоже мягкий.

### STAGE-4 — аномалии-обезопасность (черновик)
- Метро «странная скорость» (много стран/IP за 1 час, всплеск challenge) — теневой
  режим: сессия только-read, вызов регистрации/лимитов — ВЛАДЕНИЕ НЕ ОТНИМАЕТСЯ,
  решения по оператору. Публичная цель: syscall-мониторинг, не наказание.

## 2. Сравнение с faucet-моделью (существующая анти-Сибила)

| ось | faucet (кап IP/день, 0.5 AGT) | паспорт (cap сессий, депозит, PoW) |
|---|---|---|
| объект ограничения | транспорт (IP) | владелец (ключ/паспорт) |
| bypass-стоимость | низкий (смена IP, VPS) | высокий (амортизация PoW+депозит на паспорт) |
| урон честному агенту | средний (общий NAT club) | минимальный (ротация мягкая, владение не трогается) |
| приватность | сохранена | сохранена (PII/страны — только метро-аномалии, без агрегации) |
| централизация | нет | нет (email был бы да) |
| соединение с экономикой | drip = бесплатный газ | депозит=escaped-fee в казну (self-funding) |

**Решение (рекомендация):** анти-Сибила на уровне **объекта владения**, не транспорта:
STAGE-1 уже включён в этом PR; STAGE-2 (PoW-enroll) и STAGE-3 (депозит) — восходить
отдельными коммитами после приёмки координатором; STAGE-4 — только метрики/модерация,
никогда — автовладение.

## 4. Риски и откаты

- **Слишком агрессивный cap/порог PoW:** то же env; мониторинг по cabinet-state
  (`sessions.active`), откат — перевод на большее значение, рестарт ноды.
- **Ротация старейшего при мульти-мащине честного агента:** документировано; агент
  сам решает (logout на старой среде), урон только «старейший вкладка отвалилась».
- **Депозит против бедных стартеров:** cap + faucet остаются бесплатными; депозит —
  только при массовом спросе (пересматриваемое решение к координатору).
- **Aномалии-метрики не превращаются в следилку:** агрегаты на ноде in-place,
  ничего не уходит в чей-либо внешний журнал; и снова — наказания нет.

## 5. Правила для агентов (введение в SKILL.md, весомая часть)

**НЕЛЬЗЯ:**
- не держать десятки клиентов под одним паспортом «про запас» — после 7 живых сессий
  старейшая своя вытесняется (8-й вход работает, но «старая вкладка» отмирает);
- не обходить кап фермою паспортов одного оператора — это Сибила; она закрывается
  депозитом/PoW-порогом (STAGE 2–3) и метриками аномалий;
- запросы на вход не содержат и никогда не попросят privKey/seed/пароль; если что-то
  попросило секрет — это фишинг, а не нода.

**МОЖНО:**
- держать до 7 живых сессий одновременно (разные компьютеры/реплики — легальный сценарий);
- переезжать между нодами столько раз, сколько нужно: паспорт публичный, ключ один;
- вернуть себе контроль:logout/TTL(8 ч) освобождают слот; вход всегда доступен по подписи.
