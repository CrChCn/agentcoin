# AGIP-5 — Шаг 13: «внешний watchdog + стабильная точка входа» (найм `2xgELrMi`)

> Архив версии/инцидента указанной даты. Номера портов и состав нод ниже описывают тот стенд, а не обязательную топологию сети. Для своего развёртывания задайте собственные `NODE_URL`, `LOCAL_NODE_URL`, `PEER_URL` и TS bind по [JOINING.md](JOINING.md). Loopback означает компьютер исполнителя.

Дата: 2026-10-16. Цикл: ROLLOUT (снапшот → спека → песочница → 9342 → 9341 → 9335 → 9336 → фриз).
По контексту: [docs/ROADMAP-15-STEPS.md](ROADMAP-15-STEPS.md) шаг 13, [docs/HIRING.md](HIRING.md).

## Проблема
1. Публичный вход — trycloudflare **quick-туннель**: при каждом перезапуске процесса имя меняется,
   чат-приглашение и Moltbook-пост разъезжаются с реальностью (задокументировано в MORNING.md §4).
2. Watchdog работает только **внутри той машины, которую сторожит**. Если машина умерла целиком
   (Windows-апдейт, блокаут), локальный сторож умирает вместе с ней — снаружи никто не знает.
3. Состояние сторожа (`data/watchdog.json`) не видно снаружи — нельзя проверить, что он жив / сколько рестартов.

## Решение

### 1) Стабильная DNS-точка — Tailscale Funnel (решение оператора 2026-10-16)
- Стабильный публичный URL задаётся владельцем развёртывания как `NODE_URL`; прокси направляется на его `LOCAL_NODE_URL` (loopback относится к компьютеру, где работает прокси).
  (публичная нода A; TLS Funnel-ом тоже; *живое отклонение от исходного плана*: цель хотели 9336 как при
  trycloudflare, но tailscaled не может дияться в СВОЙ tail-IP как origin — 502 >22 с; loopback 9335 — 200.
  Friend-нода 9336 продолжает жить в tailnet, публичное лицо сети теперь 9335 — без перебинда и без
  расширенной экспозиции админ-эндпоинтов).
- Ничего не покупаем: домен не нужен, имя не пересоздаётся при перезапуске процесса/машины.
- Оргустановки: Funnel включается ОДИН раз по ссылке консоли (`https://login.tailscale.com/f/funnel?node=…`),
  затем `tailscale funnel --bg --set-path / "$LOCAL_NODE_URL"` на свой настроенный target. Конфиг выживает перезагрузку (persisted в своей tailnet).
- trycloudflare quick-туннель остаётся **резервным** входом до конца переводного окна (не удаляем).

### 2) Внешний watchdog — `uptime.mjs` + GitHub Actions (решение оператора 2026-10-16)
Файлы: `uptime.mjs` (корень), `test/accept-AGIP-5.mjs`, `.github/workflows/uptime.yml`.

**uptime.mjs** — одноразовый/цикловой монитор с внешним состоянием:
- env: `AGT_URLS` (comma-список публичных URL), `AGT_CHAT_URL` (нода, куда постить тревогу),
  `AGT_STATE_FILE` (где хранить down-стейт; в Actions — несуществующий путь, стейт из ленты чата),
  `AGT_DOWN_AFTER_SEC` (по умолчанию 90), `AGT_ALERT_SENDER` (по умолчанию AGTurUptimeBot… идентифицирует бота),
  `--once` — один прогон (для Actions, exit 0 всегда, кромефатальных ошибок).
- Логика: `GET /life` (5 с таймаут) по каждому URL; если чат-нода отвечает — берём свои последние
  сообщения из `GET /community/feed` и **не спамим**: повторная тревога того же URL не чаще 1 раза/55 мин;
  если down дольше `AGT_DOWN_AFTER_SEC` (для Actions — просто первое отрицательное /life) → POST `/community/send`
  `{senderHandle:'uptime-bot', text:'🚨 [uptime] <url> не отвечает >Ns'}` (публичный POST, лимит чата 10/30с);
  при выздоровлении — POST «✅ [uptime] <url> жив», `exit 0`.
- Ануляривается: безфатальные сетевые ошибки выхода наружу — монитор сам не падает.

**GitHub Actions `.github/workflows/uptime.yml`**: cron `*/5` ( Subjects: пинг публичной точки входа каждые 5 мин),
запускает `node uptime.mjs --once` с `AGT_URLS` = `<требуемый-URL>` (переменная репо `AGT_PUBLIC_URL`).
Машина-точка мёртва > 90 с → тревога в сетевой чат появляется в течение ≤ 5 мин (кварцевая гранулярность).
Парное направление «я за друга»: когда в tailnet появится вторая машина — её URL дописывается в `AGT_URLS`,
troсда GitHub Actions становится внешним сторожом и для друга (и наоборот — друг ставит тот же скрипт).

**Граничность честности:** GitHub Actions бегут только когда пингуют «снаружи» (датацентры Cloudflare away
от локального интернета-подключения) — это именно «внешний» взгляд. Рестарт третьей стороной делать нельзя
(нет SSH-доступа из Actions) — рестарт остаётся у локального watchdog.mjs, внешний — взгляд+тревога.

### 3) `GET /ops/watchdog/state` (node.mjs, публичный как /stats)
- Читает `data/watchdog.json` (если файла нет — `{ nodes: {}, startedAt: null }`).
- Возращает: `nodes: { name: { fails, restarts, sick, lastRestartAt, lastAliveAt } }`, `watchdogAliveHint` —
  `lastRestartAt`/`lastAliveAt` в ISO. **Read-only**, админ-ток terapia не нужен, консенсусу безразличен.
- Нода не обязана отдавать его братьям (это про локальную машину), но через tailnet/Funnel он виден —
  внешний смотряший мониторит и его.

## Запреты (что нельзя)
- Не трогать консенсус, эскроу-математику, формат chain.json — AGIP-5 их не изменяет (chain-совместимость 100%).
- Не удалять trycloudflare-туннель до полного переезда на Funnel.
- Не хардкодить URL: всё через env (`AGT_PUBLIC_URL` в репо, `AGT_CHAT_URL` в скрипте).

## Приёмка (accept-AGIP-5.mjs, красно-зелёный)
1. Песочница 9343: `GET /ops/watchdog/state` → 200, JSON с полем `nodes`;
2. Монитор против живой песочницы: `--once` → exit 0, в ленте чата НЕ появилось тревоги;
3. Монитор против мёртвого порта (`AGT_DOWN_AFTER_SEC=1`): тревога `🚨 [uptime]` появляется в чате
   песочницы; повторный прогон в течение 1 ч → («трёхступенчатая» тишина) новых тревог нет;
4. Фун-«выздоровление»: снова поднять цель → `✅ [uptime] ... жив` в ленте (или отсутствие новых тревог при
   недоступном чат-ноде — деградация в лог, не в fail);
5. Лестница: 9342 → 9341 → 9335 → 9336 — `/ops/watchdog/state` 200 на каждой (read-only, шаддинг → ретрай);
6. Финальная сверка: единый tip на 9335/9341/9342/9336, chainValid=true, ни одного рестарта из-за AGIP-5.
7. (внешняя) `tailscale funnel status` показывает прогонённый ли Funnel; публичный `curl` на ts.net URL → 200 `/life`.
   При недоступности Funnel (жидкая ссылка включения) — честный маркер «DNS-точка ожидает клика оператора».

## Откат-план
- Код: pure-additive (новый endpoint + новые файлы) → `git revert` коммита AGIP-5, рестарт нод по обёрткам.
- Funnel: `tailscale funnel reset` (вернёт(a tracker) trycloudflare как единственный вход в течение окна отката).
- Данные не меняются — снапшот `data/backup-*` не требуется восстанавливать.
