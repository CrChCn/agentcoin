# AGIP-7 — Комиссия по инциденту 9342: конец peer-карантина, «сеть как часики»

Дата: 2026-10-16 · Автор: Buffy (операторский агент) · Статус: внедрено в день инцидента

## Инцидент одним абзацем

Нода 9342 неделями стояла на собственном заглухшем форке (4707–4709 блоков против
~4810 у кластера). Все её пиры накопили по 3 strike с причиной
`fork adopt failed: fork_not_heavier` → `blockedUntil` на 24ч → нода перестала
слышать кластер → её тонкий майнер (зомби-процесс, не писавший ни лога, ни
heartbeat) продолжал продлевать форк → голосование вечно «not heavier» →
карантин вечен. Лечение руками: чистка peer-meta + подмена chain.json.

## Комиссия

- **Web-аудитор (researcher-web)**: сверил с reference-реализациями. Bitcoin Core
  (headers-first, `headerssync.cpp`) и geth downloader НЕ штрафуют пира за
  валидный, но проигравший форк; санкции — только за доказанную некорректность
  данных (невалидный PoW/подпись/консенсус-правила). Вердикт «fork проиграл» —
  это выбор цепи, а не нарушение. Источники:
  developer.bitcoin.org/devguide/p2p_network.html, bitcoin/bitcoin@headerssync.cpp,
  ethereum/go-ethereum@eth/downloader.
- **Код-аудитор (Buffy)**: нашёл в `sync.mjs` strike на `fork_not_heavier`
  (log `forks.json` data-node3: 6+ записей `our=512 cand=1024` и т.п. —
  валидные живые форки кластера отвергались и штрафовались), отсутствие клапана
  при полной блокировке пиров, и зомби-лок `miner-client.mjs` (pid жив,
  цикла нет — гвард `process.kill(pid,0)` пропускал).

## Root causes → перманентные фиксы (все внедрены)

1. **Страйк за проигравший валидный форк — удалён.**
   `sync.mjs`: `isChainChoiceVerdict()` — `fork_not_heavier`, `no_blocks`,
   `fork_height_mismatch` НЕ штрафуют пира. Страйки остаются только за
   доказанные нарушения: `header hash/PoW fail`, `difficulty rule violation`,
   `invalid block *`, `header/body hash divergence`.
2. **Клапан самопомощи против изоляции.** `syncAll()`: если ВСЕ пиры
   заблокированы И наш tip протух (>300с) → снимаем `blockedUntil` (страйки
   сохраняются в истории!) и слушаем сеть заново. При свежем tip клапан молчит —
   обход банов невозможен.
3. **Майнер не закрепляет форк.** `miner-client.mjs`: при `tipAgeSec > 300`
   (или `fresh=false`) слайс пропускается — ждём sync ноды.
4. **Зомби-детект майнера.** Гвард лока сравнивает `data-miner/heartbeat`
   ( pulse каждые 10с), при молчании >90с живой pid считается зомби и лок
   забирается заново (инцидент: майнер «уже работает pid 5844» молча висел).
