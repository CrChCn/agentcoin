# AGT-LIGHTNING — микроплатежи и каналы (дизайн ≠ обещание)

## Зачем
AGENTCOIN нужен «lightning-слой»: мгновенные микроплатежи (MAGT) между агентами
по работающим каналам, без записи каждого пинга в общий блокчейн, но с
ончейн-арбитражём в спорах. v1 уже работает сегодняшними рельсами L402,
v2 — state-каналы в дизайне ниже.

## v1 (работает сейчас)
- **Pay-per-mine через L402**: агент покупает майн-тикет на рельсе CyberGuard
  (`GET /mine/l402/ticket` → BOLT11-инвойс в сат) → платит → `POST /mine/l402
  {miner, paymentHash}` → нода проверяет proof-of-payment (одноразовый) и майнит.
  Ничего лишнего в цепи: в блоке только сам блок, тикеты — вне-цепь.
- Это уже «молния-стайл»: сат ↔ AGT-работа, мгновенно, без блоков на каждый чих.

## v2 (дизайн, AGT-каналы) — правила
1. **Канал = 2-of-2 подписившихся сторон и funding-tx**: A открывает канал к B
   обычной ончейн tx с memo `aln|fund|<channelId>|<peer>`, сумма = ёмкость канала.
2. **Обновления вне цепи**: взаимно подписанные состояния баланс
   `{seq, meA, meB}` (ed25519). Последний seq — единственный, кто имеет силу.
3. **Закрытие**: любая сторона публикует состояние с наибольшим seq через
   memo `aln|close|<channelId>|<seq>|<balA>|<balB>`; нода-валидатор сверяет
   подписи обеих сторон и seq при валидации блока.
4. **Сгон (fraud-proof)**: если сторона публикует СТАРЫЙ seq, другой имеет
   T_MIN блоков на `aln|fraud|<channelId>|<seq>` с более свежим состоянием —
   старый seq аннулируется, жулик наказывается пермабаном по SecurityController.
5. **Микровыплаты**: агент платит на канал-инвойс MAGT (1 AGT = 1e6 MAGT) —
   хост-нода ведёт счётчик, раз в N выплат чейн-сетлмент `aln|settle|...`.
6. Anti-DoS: открытие канала — пустое «клеймо» fee 0.01 AGT (как в DXE).

## Интеграция с терминалом агентов
В терминале `http://<нода>/terminal` — вкладка «Микроплатежи»: создать канал,
посмотреть баланс канала, сплести MAGT-инвойс между двумя агентами. v2 входит
в силу так же, как DXE — только по passed-предложению в говернанс.
