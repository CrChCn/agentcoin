# Мост Agentcoin ↔ EVM — v1. Контрольная точка 1: ядро, архитектура, модель угроз

Статус: исследование выполнено по коду (`core.mjs` 1640 строк, `node.mjs`, сообщения мемпула, тесты `test/`).
Реализация (контракты, сервисы, тесты) — после утверждения этой архитектуры владельцем.
Основная сеть и реальная ликвидность этим документом НЕ запускаются.

## 1. Отчёт о возможностях ядра

### 1.1. Финальность, выбор цепи, реорганизации
- Выбор цепи — **наибольшая суммарная работа** (Bitcoin-style): `adoptFork` принимает
  кандидата только если `candWork > ourWork` (`core.mjs`, ~1315–1353). «Длиннее» ≠ «лучше».
- **Финалити-гаджета и чекпоинтов высоты нет.** Реорганизация — штатное событие:
  вытесненные хвосты архивируются в `forks.json` (последние 20).
- Параметры темпа: блок ~30 с (`BLOCK_INTERVAL_SEC`), ретаргет каждые 10 блоков,
  сложность 8–20 бит. Эмиссия 50 AGT/блок, halving каждые 210k, cap ~21M.
- Вывод для моста: финалность только вероятностная. Глубина подтверждения K
  выбирается по истории `forks.json` (максимальная наблюдённая глубина реорга + запас),
  а не назначается произвольно. Опасный реорг/конфликт наблюдений = стоп направления.

### 1.2. Можно ли заблокировать AGT консенсусом с разблокировкой по событию моста?
**Нет, без изменения консенсуса.** Замок `CONSENSUS-FREEZE.md` (2026-11-15): запрет новых
полей, дайджестов, схем адресов и типов транзакций в `core.mjs`; новая механика — только
поверх (мемпул-политики, API, офчейн), не внутри.
- Штатные условные примитивы: **эскроу** (релиз требует подпись получателя + подтверждающую
  подпись отправителя, `verifyEscrowTx`) и **казна 2-of-3** (расход с адреса казны требует
  вторую подпись из allowlist, `verifySecondSig`, AGIP-4). Оба — про фиксированные ключи,
  а не про «событие внешнего моста» и не про порог m-of-n федерации.
- Честная квалификация v1: **кастодиально-федеративная**. Блокировка = обычный перевод
  на vault-адрес федерации; разблокировка = обычный перевод с vault (вариант А: подпись
  оператора vault + 1 подпись аттестора через механику 2-of-3; вариант Б: подпись оператора
  по журналу офчейн-аттестаций — слабее, только если А невозможен операционно).
  Ограничения кастодиального варианта — в §10.
- Протокольный апгрейд (новый тип `bridge_lock`/`bridge_release` в консенсусе) — отдельное
  решение владельца со снятием моратория, регрессионными тестами и раскаткой на 3 ноды.
  В v1 **нулевых изменений консенсуса не требуется**: мемы — свободная строка в подписываемом
  дайджесте, новые API-маршруты и мемпул-политики — вне `core.mjs`.

### 1.3. Подписи
- **ed25519** через `node:crypto`. Адрес `AGT` + 32 hex + 8 hex чек-суммы; две канонические
  схемы (обе — консенсус): от текста SPKI (`addressFromPub`: sha256d) и от сырых 32 байт
  (`addressFromRawPub`: тройной sha256). Путаница схем — известная грабля онбординга.
- Дайджест v2: канонический `stableStringify` + `amountUnits` (см. 1.5); подпись покрывает
  `{from, fromPub, to, amountUnits, nonce, ts, memo}`. Привязка адреса к ключу строгая
  (аудит P0-1: чужой ключ под чужой адрес не проходит).
- EVM-сторона требует **отдельные ECDSA-ключи** подписантов (узел их не знает и не должен).
  Разделение ключей (подпись/админ/газ) — обязательное требование, а не рекомендация.

### 1.4. Независимая проверка транзакции и включения
- `GET /txproof/{txid}`: высота, индекс в блоке, Merkle-ветка (тот же fold, что
  `merkleRoot` в ядре), заголовок блока. Проверка локально: ветка → корень → заголовок →
  связка хешей → суммарная работа через `/headers`. Этим путём уже пользуются внешние
  агенты (флоу hires-proof: txid → txproof → сверка с `header.merkleRoot`).
- Подписант обязан опрашивать **несколько независимых нод** (node1/2/3) и отвергать
  расходящиеся показания (стоп направления, §8). Доверие одному RPC — вне модели угроз.

### 1.5. Минимальные единицы и округление
- **Минимальная единица — 1e-9 AGT** («магнет», `MGNT_SCALE = 1e9`). Новая транзакция обязана
  быть точной до 9 знаков, иначе консенсус-отказ `tx_amount_not_mgnt_exact`.
- Авторитетная бухгалтерия — BigInt-replay (масштаб 19, `REPLAY_SCALE_EXP`), переживающий
  весь float-мусор legacy-истории. `balancesOf` на float — legacy-путь, не источник истины.
- Отображение на EVM: wAGT — 18 decimals; **1 магнет = 1e9 wei ровно**, вся арифметика —
  целые BigInt. `1 wAGT = 1 AGT = 1e9 магнет = 1e18 wei`. Неявного округления нет по
  построению; суммы меньше 1 магнета в Agentcoin непредставимы и должны отклоняться
  на входе с понятной ошибкой, а не округляться.
- Операционное ограничение (политика мемпула, не консенсус): переводы **> 100 AGT**
  требуют whitelist-адреса отправителя (`node.mjs`, `needWhite`). Vault и операционные
  адреса моста вносятся в whitelist заранее, иначе крупные lock/release встанут.

### 1.6. Что требует обновления протокола
По `CONSENSUS-FREEZE.md`: новые поля/дайджесты/адреса/типы tx, правки `verify*`, пороги
внутри консенсуса. **Не требует**: мем-протокол (`bridge_lock:*` в поле memo), новые
только-чтение и операторские API, мемпул-политики, офчейн-подписанты/ретранслятор,
EVM-контракты, страницы сверки. Вывод: вся v1 — без форка.

## 2. Выбор тестовой EVM-сети: Sepolia
- PoS-финалность (~2 эпохи, ≈13 мин) — чистая политика подтверждений для направления EVM→AGT.
- Живая, долгоживущая, поддерживается всем стандартным стеком (viem/ethers, OpenZeppelin,
  блок-эксплореры с API для независимой проверки Burn-событий).
- Есть предшествующий операционный опыт (тестовый wAGT-цикл), бесплатные краны.
- Перед развёртыванием проверить актуальность RPC/кранов — отдельным пунктом runbook.

## 3. Модель активов и инвариант
- Agentcoin → Sepolia: перевод AGT на vault + memo `bridge_lock:v1:…` → выпуск wAGT 1:1.
- Sepolia → Agentcoin: `burn(wAGT, agentcoinRecipient)` → разблокировка AGT с vault.
- Инвариант спокойного состояния: `locked(A GT) == circulating(wAGT)`.
  Переходные расхождения объясняются только множествами in-flight операций; поле
  `unexplained` в сверке обязано быть нулём, иначе — предупреждение + стоп новых выпусков.
- Комиссии моста — явные параметры в событии (не скрытый спред), сетевые комиссии —
  оценкой до подписания.

## 4. Протокол сообщений Agentcoin (без форка)
`bridge_lock` — обычный перевод на vault, memo строго:
`bridge_lock:v1:{bridgeId}:{destChainId}:{evmRecipient0x}:{amountMgnt}:{nonce}`.
Проверка баланса/списания/события — атомарно правилами существующего `addTransaction`.
`bridge_release` — обычный перевод с vault на `recipient` с memo
`bridge_release:v1:{bridgeId}:{burnEventId}`; исполняется оператором только при наличии
кворума аттестаций и отсутствии метки исполнения.
`eventId` (обе стороны) = `sha256d(canonical(direction, srcChain, dstChain, bridgeId,
protocolVersion, txid, logIndex/eventIndex, tokenContract, amountAtomic, parties))`.
Исполнение идемпотентно по `eventId` (хранилище исполненных + уникальный индекс);
межсетевое/межмостовое/межверсионное переиспользование исключено полями внутри id.

## 5. EVM-контракты (Sepolia, v1)
- `WrappedAGT`: ERC-20 (OpenZeppelin), 18 decimals; `mint`/`burn` — только `BridgeGateway`
  (`MINTER_ROLE`-стиль, без owner-mint); burn атомарно фиксирует `agentcoinRecipient`.
- `BridgeGateway`: порог m-of-n ECDSA над каноническим сообщением (направление, сети,
  контракты, версия, сумма, eventId); проверка уникальности подписантов; реестр
  исполненных `eventId`; проверка destChain/контракта/версии/суммы; per-op и rate-лимиты;
  раздельная пауза направлений; события мониторинга; revert с причинами.
- Обновляемость v1: **неизменяемые контракты** (без прокси). Аргумент: мост держит
  обеспечение; прокси-админ — лишняя доверенная сторона поверх федерации. Параметры
  (лимиты, пауза, ротация подписантов) — через явные admin-методы с timelock, смена
  логики — только новым развёртыванием + миграцией и отдельным решением.

## 6. Подписанты, ретранслятор, подтверждения
- Федерация 3-of-5 на тест (параметр; прод — отдельным решением о независимости).
- Подписант: своя нода/независимый RPC обеих сетей → ожидание политики подтверждений →
  подпись точного сообщения → журнал решений (без секретов) → запрет конфликтующих подписей.
- Ретранслятор непривилегирован: дубли и рестарты безопасны (идемпотентность по eventId).
- Подтверждения Agentcoin: K блоков поверх высоты lock, где K = max(наблюдённая глубина
  реорга из `forks.json` + запас, ≥ ~2 ч стены при 30-с блоках — число фиксируется после
  замера истории, не «с потолка»). Sepolia: финализированный (2 эпохи) статус Burn.
- Реорг до выпуска: отмена аттестаций, перевод в `paused`, переподтверждение.
  Реорг после выпуска: wAGT не отзывается автоматически — явная процедура (остановка,
  инвентаризация, решение владельцев); остаточный риск — в §10.

## 7. Состояния и API
Машина перевода (оба направления, с уточнением стороны в поле `direction`):
`detected → confirming → attesting → executable → completed`, боковые `paused / rejected`
(+ `cancelled` для операторной отмены без движения средств, по образцу `/queue/cancel`).
Тайм-аут клиента ≠ отмена: повторный запрос возвращает текущее состояние (идемпотентность
по `transferId`, `transferId = eventId` соответствующего направления).
- `GET /bridge/config` — версии, chainId, адреса контрактов/vault, пороги, лимиты, паузы.
- `GET /bridge/transfers/{id}`, `GET /bridge/transfers?address=` — история переходов + tx-ссылки.
- `GET /bridge/reserves` — locked, circulating, in-flight обе стороны, комиссии, unexplained.
- `GET /bridge/health` — высоты/хеши обеих сетей, свежесть, статус направлений.
- Ошибки структурированные (`code`, `retryable`, `nextAction`, `retryAfterSeconds`);
  наблюдение не распоряжается средствами по публичному адресу.
- Экран подписания: сети, актив, сумма, получатель, комиссия моста, оценка газа,
  ожидаемое получение, условия и время подтверждения.

## 8. Лимиты и управление
Per-op лимит, окно объёма, потолок обеспечения; раздельная пауза направлений;
ротация подписантов через кворум + задержка; журнал админ-действий. Пауза не меняет
получателей и не конфискует: судьба начатых операций фиксируется в политике
(`executable` — дозавершить или вернуть отправителю, `confirming/attesting` — заморозить
до разбора). Срочная остановка отделена от изменения правил.

## 9. Сверка обеспечения
Страница + JSON: locked AGT (баланс vault по BigInt-replay), circulating wAGT (`totalSupply`
минус известные burn-in-flight), locked-not-minted, burned-not-released, комиссии,
`unexplained`, высоты/хеши/время обеих сетей. Контрольные точки — согласованные
(финализированная высота Sepolia + K-глубина Agentcoin). Ненулевое unexplained —
стоп выпусков.

## 10. Остаточные риски v1 (честно)
1. Кастодиальность Agentcoin-стороны: оператор vault + 1 аттестор могут сговориться;
   порог 3-of-5 действует только на EVM-выпуск. Митигация: разделение ключей, журнал,
   публичная сверка, лимиты; полное устранение — только протокольным апгрейдом.
2. Реорг после mint: необеспеченные wAGT в обращении; процедура ручная.
3. Компрометация ≥ порога ECDSA-ключей подписантов.
4. Баг EVM-контрактов до аудита (аудит — обязателен перед продом, §12).
5. Ошибка точности отображения decimals (закрыта §1.5, покрыть тестами границ).
6. Простота/остановка Sepolia-RPC (несколько независимых источников).

## 11. Вне v1
Пулы ликвидности, стейбл-обмен, листинги, гарантии цены, вторая внешняя сеть,
кредитование/доходность. Предложение по рынку wAGT/стейбл — отдельно после моста.

## 12. Приёмка (напоминание из ТЗ)
Отчёт+архитектура (этот документ) → код → воспроизводимый стенд → тесты+сверка →
runbook (стоп/восстановление/смена ключей) → риски+аудит. Прод — отдельным решением.
