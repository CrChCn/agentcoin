# CORE-P0 п.3 — версионированный canonical digest авторизационных полей

Ревизия Королера (comment 6270365807, п.3): «txDigest не связывает signature/escrow proof/вторую
подпись. Утверждение о привязке ВСЕГО содержимого к merkle сейчас неверно; для нового формата нужен
версионированный canonical digest авторизационных полей и совместимый план».

## Фактическое состояние v1 (историческая совместимость, НЕ меняется)

- `txDigest(tx)` = sha256d(JSON {from, to, amount, nonce, ts, memo}) — v1 никогда не пересчитывается.
- Подписи: `signTransaction`/`verifyTransaction`, вторая подпись казны `verifySecondSig` — обе поверх
  v1-digest.
- укрепление адресной привязки: `verifyTransaction` (P0-1) и `verifyEscrowTx` проверяют, что
  fromPub/escProof разворачиваются в ожидаемые адреса — связка адресом ЕСТЬ, но txid этих полей не
  закрепляет (два tx с разным fromPub/escProof могут делить один txid при одинаковых v1-полях).
- Правило не закрывается пост-фактум: merkle считает v1-тxid, и мерная замена подписанных полей,
  если таковые различимы где-то ещё, не изменит идентификатор. Для НОВЫХ правил это нужно закрыть.

## v2 — реализовано (код, не активировано)

Введён `tx.digestVersion === 2`, функции:

- `stableStringify` — детерминированный JSON (отсортированные ключи, undefined пропускается).
- `canonicalAuthPayload(tx, 2)` = stableStringify({
    from, fromPub, to, amountUnits (целые магенты, submagenta ОТВЕРГАЕТСЯ броском
    `tx_amount_not_mgnt_exact`), nonce, ts, memo, escProof (null/объект целиком), sig2Sig
    ('sig2-bound' если sig2 присутствует), digv: 2 }).
- `txDigestV2(tx)`, `signTransactionV2(tx, privKey)`, `verifyTransactionV2(tx)` — подпись поверх
  v2-payload;第三次 подпись (sig2) так же вычисляется поверх v2 digest при digv=2 (само поле sig2
  в payload входит как маркер присутствия, чтобы digest оставался тем же между подписанием tx
  и проверкой второй подписью).
- v1 API не затронут: `txDigest`/`signTransaction`/`verifyTransaction` байт-в-байт как в main.

Тесты: `test/core-p0.mjs` T21a–f (rapture v1/v2, tamper fromPub/escProof меняет digest, submagenta
отвергнут, версия явная).

## План активации (совместимая схема, отдельным решением сети)

1. **Нодов-флаг, не файл-формат:** активация только явной схемой (как CORE-P0-высота):
   `AGT_TX_DIGEST_V2_HEIGHT` — с этого блока узел НОВОГО кода принимает только digv=2 tx,
   узлы старого кода такую же ветку отвергнут как `tx_bad_signature` (v1 verifier не поймёт v2).
2. **Не случайно:** молча смешивать v1/v2 в мемпуле на границе активации нельзя; валидатор при
   включённом пороге отвергает內 tx с digestVersion !== 2 для обычных подписей (эскроу-расходы —
   через свои правила verifyEscrowTx, независимо от digv).
3. **Миграция маем:** майнеры переключают client-подпись на signTransactionV2 раньше высоты;
   блоки с v2-сигнатурами до активации не проходят v1-verifier — «pre-switch window» запрещён.
4. **Checkpoint/policy:** активация фиксируется в общем checkpoint-политики (как CORE-P0), чтобы
   расхождение правил между нодами не было допустимо; краевые fail-closed ошибки — то же правило,
   что и AGT_CORE_P0_HEIGHT (п.5).
5. **Совместимость истории:** цепь до высоты активации валидируется v1-правилами до бесконечности;
   никакой замены txid/пересчета merkle в неактивированных блоках не происходит.
