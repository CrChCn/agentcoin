# AGT Decentralization v3 — дизайн консенсуса

Дата: 2026-10-14. Статус: внедрено (изолированные тесты пройдены, живые ноды обновлены).

## Проблема v2

До v3 сеть AGT была по сути **авторитарной**: нода 9335 майнила и определяла истину,
а нода 9341 была follower'ом — принимала чужие блоки почти без проверки и не могла
голосовать. Это противоположно тому, что делает Bitcoin децентрализованным.

Дыры v2 (реальные, найдены при аудите):

1. **Не проверялось правило сложности.** Пир мог подсунуть блок с
   `difficultyBits=8` вместо требуемых 11–14 бит: PoW-хеш валиден ПРОТИВ
   заявленной сложности, поэтому нода «принимала» дешёвые блоки → дешёвая
   атака форком (по сути 100% работой за 1% мощности).
2. **Один взгляд на выбор.** Более высокая цепь принималась молча
   (longest-chain), сравнения работы не было.
3. **Валидация тел неполная.** Мерл и хеш проверялись, но coinbase
   (эмиссия не выше reward) и подписи транзакций — нет.
4. **Нет репутации.** Плохой пир мог присылать мусор бесконечно.
5. **Транзакция не расползалась** — только ждала блока локального майнера.

## Решение v3 (свой дизайн с учётом опыта)

| Урок | Кто научил | Что взяли |
|---|---|---|
| fork choice по суммарной РАБОТЕ, не по высоте | Bitcoin | `chainWork()`, голосование форка сравнением работы |
| «не верить никому» — полная валидация каждого блока | Bitcoin, Monero | `validateBlockAgainstChain()`: prev/hash/PoW/правило сложности/merkle/coinbase/подписи |
| headers-first (дешёвый отказ до загрузки тел, 80 байт на блок) | Bitcoin headers-first | `GET /headers`, проверка PoW + правила сложности на заголовках |
| детерминированная сложность из самих заголовков | Bitcoin (retarget из header times) | `expectedDifficultyBits(chain)` — зеркало `nextDifficulty()` |
| ASIC-независимость соли | Monero (RandomX) | не применяли: размыкание лишь в будущем (демо-цепь) |
| кольцевые подписи/приватность | Monero | не применяли (out of scope v3) |
| fee-none микроплатежи | Nano | уже было: fee = 0 |
| choke/репутация пиров | IPFS/BitTorrent | strikes: 3 → отсечение пира на 24ч (`peer-meta.json`) |
| транзакции живут до блока | Bitcoin mempool | персистентный мемпул БЕЗ доверия: майнер пакует только валидные |

### Правила консенсуса (v3)

1. **Genesis pinning**: genesisHash обязателен для чужой сети.
2. **Headers-first**: `GET /headers?from=` → линия заголовков проверяется
   дёшево (сцепка prev → PoW → **правило сложности**). Отказ → strike.
3. **Полная валидация тел**: каждый блок против нарастающего префикса
   (`validateBlockAgainstChain`), включая coinbase ≤ blockReward и подписи.
4. **Голосование best-chain**: развилка сравнивает `chainWork` от точки
   расхождения (точка ищется диффом полной линии заголовков). Тяжелее —
   канон; наш хвост архивируется в `forks.json` (ничего не удаляется молча).
5. **Reputation**: strikes за невалидные заголовки/блоки/данные; 3 strikes
   → отсечение пира на 24ч. Честный блок медленно восстанавливает.
6. **Mempool**: персистентен (`mempool.json`), при упаковке майнером
   фильтруется по балансам и подписям (`usableMempoolTxs()`), устаревшие
   после re-org дропаются с атак-журналом.
7. **TX-gossip**: `POST /tx` после приёма рассылает транзакцию пирам;
   дубль у пира не ре-экспортируется (без петель).

### Что это даёт

- **Живая нода-равноправная**: 9341 сама валидирует, голосует, может
  отвергнуть плохой блок 9335 (и наоборот — сеть симметрична).
- **Дешёвая атака дешевле**: подсувать лёгкие блоки теперь нельзя — они
  не проходят детерминированное правило сложности.
- **51%-атака работает только при реальной работе**: чтобы вытеснить
  честный хвост, надо намайнить тяжёлый валидный форк (у нас 51% = мощность,
  а не количество).
- **Отказ в двух местах**: правило сложности отсекает дешёвые форки,
  голосование по работе отсекает «честные, но лёгкие».

### Ограничения (честно)

- Нет динамического размера блока (Monero) и кольцевых подписей.
- NO dynamic fees: fee = 0 — на демо-масштабе ок.
- Голосование — по работам единственного пула хеш-мощи (майнеры все на
  одной машине): честный шахтёр = majority; настоящая децентрализация
  мощности — будущая ступень (несколько пиров с real own miner'ами).
- `forks.json` — аудит-подход: полный UTXO-reorg с откатом запросов
  не делается (коммьюнити-аккаунты должны читать текущий канон свежим synx).

## Тесты (пройдены 2026-10-14)

- `p2p/fork-vote-test.mjs` (жертва = копия основной цепи):
  - честный тяжёлый форк (атакующий `honest-fork 116`, 24 блока × 13 бит):
    точка развилки 116 найдена, голос за кандидата (768 > 448),
    RE-ORG принят: dropped=14, добавлено=24; `forks.json` записал.
  - easy-extend (12 лёгких блоков, bits 8 вместо 11, PoW-валиден):
    отвергнут **на заголовках** (`нарушает правило сложности`),
    пир получил strike. Ничего в цепь не попало.
- `validateBlockAgainstChain` против живой цепи (145 блоков):
  все блоки ≥2 проходят детерминированное правило (блок 1 — исторический
  квирк, добыт до ужесточений; живой append никогда его не валидирует).
