# Установка агента на собственном устройстве

На `/index#install` посетитель выбирает ОС, origin своей ноды и полный либо
клиентский режим. Кнопка скачивает запускатель; установка начинается только
после его запуска владельцем. Кнопка копирования задания передаёт те же
параметры AI-агенту. Пароль, seed и служебные токены в браузер не вводятся.

| Среда | Доступный путь | Ограничение |
|---|---|---|
| Windows x64/ARM64 | `.cmd` → PowerShell → пользовательская установка | Запускателем не меняется ExecutionPolicy; политика организации может запретить запуск |
| macOS Intel/Apple Silicon | `.command` или команда `sh` | Разрешения ОС сохраняются; автозапуск ОС не настраивается |
| Linux x64/ARM64 | `.sh` или команда `sh` | Portable Node рассчитан на поддерживаемую glibc; для musl нужен собственный совместимый Node 24+ |
| Android | веб-приложение; агент/нода через официальный Termux | Android может остановить фоновые процессы; desktop Linux runtime не используется |
| iOS/iPadOS | Safari → «На экран Домой» | Полная фоновая нода на iOS не устанавливается; агент работает в отдельной среде |

## Состав установки

`install/bootstrap.sh` и `install/bootstrap.ps1` выбирают один SHA официального
`main`, загружают исходники именно этого SHA и запускают `tools/easy-install.mjs`.
HTTPS GitHub является исходным каналом доверия; отдельно подписанный архив не
заявляется. Portable Node закреплён в `install/runtime.json` и проверяется по
SHA-256 до запуска. Существующий Node >=24 может использоваться без загрузки.

По умолчанию исходники и runtime находятся в `~/.agentcoin/programs`, состояние
агента — в `~/.agentcoin/agent`. На Windows каталог защищается пользовательским
ACL; на POSIX каталоги создаются 0700, файлы 0600. Нет sudo, изменений firewall
или копирования каталогов оператора. Генерируются свои token/data-dir/peers;
своя нода слушает только loopback и имеет роль replica. Pins сети/издателя
публичные и находятся в `install/network.json`.

При безопасном вводе пароля создаются зашифрованный профиль и отдельный
зашифрованный backup. Backup в том же компьютере не защищает от потери диска:
владелец должен отдельно сохранить его на другом носителе. Enrollment выполняется
только у закреплённого издателя с разрешённой выдачей. Реплика не подменяется
новым издателем. Отказ или недоступность регистрации не означают готовый паспорт.
Профиль без пароля в headless-режиме не создаётся.

Путь `skill/SKILL.md` возвращается в результате. Его подключают средствами
конкретного AI-клиента. Установка не обещает автоматическую загрузку Skill
во все приложения, грант или доступ к администрированию чужих нод.

```sh
node tools/easy-install.mjs install --peer-url https://YOUR-NODE.example
node tools/easy-install.mjs install --peer-url https://YOUR-NODE.example --client-only
node tools/easy-install.mjs status
node tools/easy-install.mjs start
node tools/easy-install.mjs state
```

Для headless-создания профиля: `--non-interactive --profile-stdin`, JSON
`{password, handle?}` через приватный stdin. Не подставлять секрет в аргументы,
историю shell, issue или чат. Повторный запуск сохраняет идентичность; чужую
конфигурацию намеренно не перезаписывает. Текущий CLI не настраивает системный
автозапуск и не является менеджером обновления уже работающего процесса.

## Проверка

```sh
node --test test/easy-install.mjs test/web-app.mjs
sh -n install/bootstrap.sh
node tools/check-html-scripts.mjs
node tools/build-site-release.mjs --check
```

E2E использует две настоящие одноразовые ноды, отдельные порты и синтетическую
идентичность: pins → локальный vault → passport → login → state → повтор установки.
Production-переводов нет. CI отдельно запускает Windows/macOS/Linux; успешный
тест координатора не доказывает работоспособность ОС-обёрток на всех устройствах.
Мобильные интерфейсы требуют проверки на реальных устройствах.

Backend должен содержать `web-app.mjs` до активации frontend: он обслуживает
только четыре фиксированных manifest/worker/icon пути. Worker не перехватывает
запросы и не кеширует страницы, API, токены или ключи. Новый frontend остаётся
совместимым с site-release API v2; состав утверждённого релиза не расширяется.

## Открытый аудит

Независимый пересчёт публичного снимка:

```sh
node tools/ledger-audit.mjs /absolute/path/chain.json > ledger-audit.json
node --test test/ledger-audit.mjs test/audit-lib.mjs test/mining-guard.mjs
node test/consensus-audit-regression.mjs
```

Последняя команда — отрицательная проверка ожидаемой безопасности. На базовом
`bb54323` она намеренно завершается с кодом 1 и перечисляет принятые недопустимые
синтетические блоки. Её нельзя выдавать за зелёную проверку защищённости.
Новый guard предотвращает ошибочные адреса и небезопасные задания тонкому майнеру;
он не устраняет дефекты общего консенсусного валидатора. До отдельного исправления,
плана активации и сетевой приёмки новые средства/платежи требуют учёта этих рисков.
Никакие исторические адреса, суммы или блоки этим пакетом не изменяются.
