# Императорский холодный кошелёк AGT («wallet.dat»-формат)

Дата: 2026-10-18. Статус: инструмент готов, selftest пройден (CREATE→SIGN→VERIFY, подмена отвергается, смена пароля, восстановление из слов даёт идентичный адрес).

## Зачем
Личное хранилище «как wallet.dat у Bitcoin»: приватный ключ **никогда не лежит на нодах**,
шифруется твоим паролем в отдельный файл и восстанавливается из бумажной мнемоники
через 5, 10, 20 лет, даже если репозиторий изменится.

## Файлы
- [tools/emperor-wallet.mjs](../tools/emperor-wallet.mjs) — сам инструмент (только Node ≥ 18, БЕЗ npm-зависимостей);
- [tools/emperor-create.cmd](../tools/emperor-create.cmd) → [emperor-create.ps1](../tools/emperor-create.ps1) — создание со скрытым вводом пароля;
- [tools/emperor-restore.cmd](../tools/emperor-restore.cmd) → [emperor-restore.ps1](../tools/emperor-restore.ps1) — восстановление из слов (скрытый ввод);
- файл хранилища по умолчанию: `data-emperor/emperor-wallet.empw` (в .gitignore, в git никогда не попадает).

## Как это устроено (стойкость на годы)
| Слой | Что и почему |
|---|---|
| Ключ | ed25519, PKCS8 PEM — opensли стандарт, читаемый любым Node/OpenSSL 10+ лет спустя |
| Мнемоника | BIP39 (12 или 24 слова) — соответствует контрольной сумме; SLIP-0010 ed25519 master key из seed (PBKDF2-HMAC-SHA512, 2048, salt «mnemonic») |
| Адрес | canonical `addressFromPub(pub)` из core.mjs — с теми же правилами, что и у всей сети AGT; ноде для приёма НЕ нужен твой ключ |
| Шифрование | AES-256-GCM (ключ 32 байта), KDF: scrypt N=2^17, r=8, p=1 (>128 МБ памяти на перебор одной пароль-попытки — GPU-ферме дорого) |
| Целостность | GCM-authTag + массив `address` внутри файла: неверный пароль/повреждение => расшифровка падает |
| Офлайн | create/restore/sign/verify НИКОГДА не обращаются к сети; сеть нужна только для приёма (POST /tx) и баланса |
| Секреты идут по stdin | пароль/слова передаются маркерами `PASS:`/`PASS2:`/`WORDS:` — не в argv, не в env, не в логи; PS-обёртка прячет ввод (`Read-Host -AsSecureString`) |

## Создание (5 минут)
1. Двойной клик `tools\emperor-create.cmd` (или из терминала).
2. Пароль дважды (ввод скрыт). 12 или 24 слова. Метка — любая.
3. Экран покажет один раз:
   - адрес кошелька (`AGT...`) — можно печатать хоть на заборе;
   - МНЕМОНИКУ — записать НА БУМАГУ (два разных физических места), не фото, не облако;
   - хэш мнемоники — помогает потом проверить, что восстановил правильные слова.
4. Файл `data-emperor/emperor-wallet.empw` — и есть твой «wallet.dat»: копируй на 2–3 носителя
   (USB, второй ПК, офлайн-диск) вместе с этой инструкцией.

## Проверить, что восстановление работает — ОБЯЗАТЕЛЬНО, сразу
```
tools\emperor-restore.cmd          → data-emperor/restored.empw
node tools/emperor-wallet.mjs info data-emperor/restored.empw   (экранный ввод скрывать нечего)
```
Адрес в `info` ДОЛЖЕН совпасть с оригиналом. Потом удали тестовый файл `restored.empw`.

## Сигнатура расхода (не задаёшь ноде ключ)
П与自己 нода получает ТОЛЬКО готовую подписанную tx:
Твоя нода принимает ТОЛЬКО готовую подписанную tx:
1. готовишь файл `tx.json`: `{ from: <адрес кошелька>, to: <адрес получателя>, amount, nonce, ts, memo }`;
2. `node tools/emperor-wallet.mjs sign --tx tx.json` → `signed-tx.json` (спросит пароль обёрткой ps1 либо stdin `PASS:`);
3. `POST /tx` с содержимым signed-tx.json на любую честную ноду (это публичный маршрут);
4. баланс: `node tools/emperor-wallet.mjs balance --node http://127.0.0.1:9335`.

## Угрозы и границы
- Скомпрометирован файл без пароля => бесполезен (AES-256-GCM).
- Известны файл + пароль => монеты уходят: пароль держи отдельно от файла.
- Бумага это НЕ абсолют: огонь/вода/потеря => два места, рассмотри стальные пластины/гравировку.
- Мнемонику/пароль НЕ вводить на сайтах, НЕ слать в чаты/issue/саппорт; «поддержка» никогда не попросит.
- Фишинг: запускай только этот локальный файл; проверяй, что `node` из Program Files, а скрипты лежат в repo.

## Восстановление «через 10 лет»
Понадобится только: Node ≥ 18, папка `tools/` инструмента, bip39-english.txt (в repo),
и бумажные слова. Если repo исчезнет — шаги формата описаны здесь и фиксируются в
коммите (commit: формат EMPW1, SLIP-0010 ed25519 master, PBKDF2 2048 «mnemonic»,
scrypt N=2^17/r8/p1, AES-256-GCM, PKCS8 ed25519, адрес = sha256d(pub)+checksum).
На любую платформе это воспроизводится ~30 строками стандартного node:crypto.

## Приёмка selftest (выполнено)
- create→sign→verify: подпись честная; TAMPER (подмена amount) — отвергнут;
- смена пароля `pass`: подпись после смены новым паролем работает;
- restore из слов: адрес идентичен (байт-в-байт);
- все тестовые файлы удалены, каталог data-emperor почищен.
