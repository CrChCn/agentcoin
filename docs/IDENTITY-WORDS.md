# Единый формат identity: слова + имя + адрес

Канон: адрес `AGT…` не меняется никогда. Слова и имя — это способы
держать и показывать ТОТ ЖЕ ключ. Уже выданные паспорта валидны,
перевыпуск не нужен, деньги не трогаем.

## Что уже работает (CLI, локально, без сети)

```bash
cd agentcoin
# 1. человеческое имя твоего адреса (без секретов, можно показывать всем)
node agt-skill/agent-profile.mjs petname ~/.agentcoin/profile.json
# → {"address":"AGT…","petname":"humor-stove-best","display":"ivan-123 · humor-stove-best · AGT8418d…dcb0"}

# 2. слова твоего адреса (ПАРОЛЬ через stdin, слова — НА БУМАГУ, не в чат/фото)
echo '{"password":"…"}' | node agt-skill/agent-profile.mjs words ~/.agentcoin/profile.json

# 3. вход с другого устройства по словам (нового файла ещё нет)
echo '{"password":"НОВЫЙ-пароль-12+","mnemonic":"слово … слово","label":"ivan-123"}' \
  | node agt-skill/agent-profile.mjs create ~/.agentcoin/profile.json
# адрес обязан совпасть байт-в-байт — сверь `public` до и после
```

## Миграция существующего паспорта (включая адрес с телефона)

1. Там, где ключ живёт (телефон): `backup` в зашифрованный файл + `words` на бумагу.
2. На новом устройстве: `restore` по файлу ИЛИ `create` по словам — что удобнее.
3. Сверка: `public` обоих профилей — адрес совпадает → миграция удалась.
   Не совпал → стоп, разбираемся, старый файл не удаляем.
4. Handle (`ivan-123`): кто первый занял в enroll — того и имя. Новым —
   `handle-claim` тем же ключом (уникальность проверяет нода).
5. Отпечаток `слово-слово-слово` — чистая витрина из словаря `bip39-english.txt`
   (фиксированные 2048 слов), считается локально, в цепь не пишется.

## Две адресные схемы (важно)

Один и тот же ключ даёт РАЗНЫЕ адреса в двух схемах — это нормально,
деньги и паспорта при этом не раздваиваются: каждая запись живёт в своей схеме.

- **Паспортная (CLI, agent-identity):** адрес = хеш ТЕКСТА SPKI PEM ключа
  (`canonicalAgentPublicKey` + `addressFromPub`). Так выданы паспорта и handle.
- **Браузерная (create-wallet, agt-tx, слова):** адрес = хеш СЫРЫХ 32 байт
  ключа (`addressFromRawAgentPub` в `agent-identity.mjs` — та же формула,
  что `addressFromPubHex` в `site/js/agt-tx.mjs`).

Правила:
1. Привязка адрес↔ключ проверяется всегда ВНУТРИ своей схемы, смешивать нельзя.
2. Вход владением ключом (TOFU, `/cabinet/challenge` с полем `pub`) принимает
   обе формы: PEM идёт общим паспортным кодом, сырой hex — отдельным
   каноническим сообщением (см. `rawOnly` в `cabinet.mjs`). Подпись сверяется
   с тем же сообщением, подмена невозможна.
3. Слова восстанавливают ТОТ ЖЕ сырой ключ → тот же браузерный адрес
   байт-в-байт. Паспортный адрес того же ключа — другой, и это ожидаемо.
4. PIN ставится поверх любой key-only сессии (`/cabinet/pin/*`) и работает
   с обоих типов адресов. Брутфорс: 5 ошибок → замок 15 минут на адрес.

## ПИН, пароль, слова — кто есть кто

- **Слова (12)** — мастер-доступ. Восстанавливают ключ где угодно.
- **Файл + пароль (12+ символов)** — повседневный доступ. Пароль знает только твоя голова.
- **ПИН** — только быстрая разблокировка на ЭТОМ устройстве, не способ входа
  с чужого. Если ПИН не устанавливал — его нет, входи файлом/словами.
- Ноде и сайту нельзя отдавать: слова, пароль, приватник. Только адрес,
  подпись челленджа, паспорт. Это не меняется.

## Формат витрины (единый)

`handle · слово-слово-слово · AGTxxxxx…xxxx`
пример: `ivan-123 · humor-stove-best · AGT8418d…dcb0`
