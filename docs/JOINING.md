# Как подключить собственную ноду Agentcoin

Нода не привязана к компьютеру автора проекта. Адреса участников и способ доступа выбирает владелец каждого развёртывания. В репозитории нет обязательного публичного сервера: `bootstrap.json` поставляется с пустым списком.

## 1. Подготовить свою среду

Установите Node.js 24 LTS и скачайте проект:

```bash
git clone https://github.com/CrChCn/agentcoin
cd agentcoin
node --version
```

`127.0.0.1` всегда означает **компьютер, исполняющий команду или браузер**. Он не указывает на компьютер автора или другого участника. Порт ниже — пример стандартного порта приложения; его можно заменить свободным портом своей машины.

## 2. Запустить свою ноду

```bash
export NODE_PORT=9335
export AGT_BIND=127.0.0.1
export AGT_DATA_DIR="$PWD/data"
node node.mjs "$NODE_PORT"
```

Каждый отдельный процесс ноды должен иметь собственный каталог `AGT_DATA_DIR`. Два процесса не должны одновременно записывать одну цепь и один реестр кошельков.

В другом терминале укажите адрес этой же ноды:

```bash
export LOCAL_NODE_URL="http://127.0.0.1:${NODE_PORT:-9335}"
curl -fsS --max-time 5 "$LOCAL_NODE_URL/health"
curl -fsS --max-time 15 "$LOCAL_NODE_URL/life"
```

`/health` проверяет доступность сервиса, `/life` — также состояние цепи. `fresh:false` означает возраст последнего блока; само по себе это не доказывает отставание от другого пира.

## 3. Выбрать участников сети

Получите доступный `PEER_URL` у выбранного участника. Это может быть его публичный HTTPS-адрес или адрес в вашей общей VPN. Проверяйте `chainId` и genesis сети; обнаружение пира не заменяет валидацию его блоков.

```bash
# Перед выполнением задайте PEER_URL — URL выбранного вами участника.
: "${PEER_URL:?Set the reachable peer URL for your deployment}"
node -e 'process.stdout.write(JSON.stringify({peer:process.env.PEER_URL}))' |
  curl -fsS --max-time 15 -X POST "$LOCAL_NODE_URL/peer/add" \
    -H 'Content-Type: application/json' \
    -H "x-admin-token: ${AGT_ADMIN_TOKEN:-}" --data-binary @-
curl -fsS --max-time 30 -H "x-admin-token: ${AGT_ADMIN_TOKEN:-}" "$LOCAL_NODE_URL/sync-now"
```

Переменная `PEER_URL` должна быть экспортирована (`export PEER_URL=...`). Админ-команды адресуются вашей ноде; в token-режиме используйте её локальный токен. Не передавайте админ-токен чужому пиру.

Можно настроить собственный список URL в `bootstrap.json`, если вы используете bootstrap-механизм. Пустой список намеренный: без явно настроенных пиров нода не подключается к существующей сети автоматически.

## 4. Настроить доступ к собственной ноде

- Локальный режим: `AGT_BIND=127.0.0.1`, доступ только с этой машины.
- Mesh-VPN: создайте свою сеть либо используйте приглашение от выбранного участника. Привязка и ACL настраиваются владельцем; никакая конкретная tailnet не обязательна.
- VPS или HTTPS-прокси: укажите свой `NODE_URL` для клиентов и свой `PEER_URL` для соседей. Публичный API и администрирование имеют разные полномочия.

Для Windows-обёртки TS укажите **собственный IP интерфейса** в `AGT_TS_BIND` или файле `data-agtx/ts-bind.txt` (один IP, файл не публикуется). `run-node-ts.cmd` использует `AGT_ADMIN_MODE=token`. Без настройки TS не запускается; wildcard-bind не подставляется автоматически.

`NODE_URL` — выбранная точка подключения клиента, `LOCAL_NODE_URL` — адрес локального сервиса на компьютере исполнителя, `PEER_URL` — явно выбранный сосед. Эти переменные не являются зашитыми адресами сети.

## 5. Идентичность и средства агента

Для постоянного кабинета и локальной подписи используйте [инструкцию кабинета](AGENT-CABINET-PORTABILITY.md). Не создавайте и не восстанавливайте приватный ключ через чужую общую ноду. Операторский `/wallet/create` относится только к собственной доверенной ноде; старый `/tx/sign` не заменяет noncustodial-клиент.

| Действие | API |
|---|---|
| Публичный баланс | `POST /balance {"address":"AGT…"}` |
| Передача уже подписанной операции | `POST /tx` |
| Паспорт и кабинет | См. инструкцию кабинета |
| Состояние сети | `GET /info`, `/life`, `/peers/meta` |

## Диагностика без удаления данных

- Нет соединений: проверьте свои `PEER_URL`, VPN/ACL, HTTPS, `chainId` и genesis.
- Старый tip: сравните высоту, hash и суммарную работу с доступными участниками; проверьте майнинг и синхронизацию.
- `chainValid:false`: сохраните данные и логи для разбора. Не удаляйте `data/`, кошельки или паспорт ради автоматического «лечения».
- Повторная нода на том же компьютере: выберите другой свободный порт и отдельный `AGT_DATA_DIR`; это локальный тест, а не независимый оператор.
