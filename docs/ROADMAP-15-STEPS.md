# План из 15 действий — грамотно по порядку (агент AGT, цикл после аудита 2026-10-15)

Порядок задан принципом: «сначала замок, потом стены, потом вывеска» —
безопасность → гигиена → тестовая инфраструктура → процесс внедрения → фичи → федерация → публичный рост.
Каждый шаг с критерием приёмки; шаг не закрыт, пока критерий не выполнен живьём.

---

## Этап I — Замок (P0-безопасность)

### Шаг 1. Активировать AGT_ADMIN_TOKEN на живых нодах
- Задать токен оператором (без записи в git-файлы), расставить env в Среды запуска нод.
- Прокат по лестнице: 9342 (канарейка) → 10 мин наблюдения → 9341 → 9335 (публичная) → 9336.
- **Приёмка:** всё по одному процессу на порт, /life 200 на всех, ни одного 500.

### Шаг 2. Acceptance ТЗ-1 извне и локально
- Через туннель без токена: `POST /security/unban` ожидаемо → **401**.
- Локально с заголовком `x-admin-token` → штатный ответ (200/404).
- **Приёмка:** curl-лог прикладывается к AUDIT-доке.

### Шаг 3. Актуализировать и закоммитить аудит-фикс-док
- Коммит `docs/AUDIT-2026-10-15.md` со статусами «сделано/ждёт».
- **Приёмка:** `git status` чистый по docs/.

## Этап II — Гигиена (P1)

### Шаг 4. ТЗ-2: `audit-lib.mjs` — единый источник аудита
- Вынести `recalcFromChainFile` + `auditBalances` (с opinion-скипом, 503-ритраями, NaN-скипом)
  из auto-miner.mjs и health-check.mjs; оба импортируют модуль.
- **Приёмка:** ручной аудит на 9335/9341/9342 — 0 несоответствий; дубли-функции удалены.

### Шаг 5. ТЗ-3: закрыть грязный git cyberguard-consult
- Коммит `src/index.js`, `src/lnd.js` (фикс 500→503 `lnd_not_ready`), push.
- **Приёмка:** `git -C cyberguard-consult status` чистый; npm test проходится.

### Шаг 6. ТЗ-4: три smoke-теста ядра в CI
- `blockReward` на высотах 0/210k/420k = 50/25/12.5;
- `signTransaction → verifyTransaction` ok; tampered digest → fail;
- `escrowConfirmDigest` двухподунсная верификация ok; tampered → fail.
- **Приёмка:** локальный `node test/*` зелёный, CI на GitHub зелёный на push.

## Этап III — Процесс (чтобы дальшейшие шаги не ломали сеть)

### Шаг 7. `ROLLOUT.md` — лестница внедрения
- 7 ступеней: снапшот → AGIP-спека → песочница (AGT_DATA_DIR + порт argv) → канарейка 9342 →
  эскалация → фриз 6 ч → откат-план. Внутри: шаблон acceptance-скрипта.
- **Приёмка:** команды в документе точные по argv/env — двоякого чтения нет.

### Шаг 8. Первый живой запуск ROLLOUT на простом эндпоинте `/peers/bootstrap`
- `bootstrap.json` в репо (официальный список пиров) + GET `/peers/bootstrap` на ноде.
- Прогнать всю лестницу: спека → песочница → канарейка → эскалация → фриз.
- **Приёмка:** `/peers/bootstrap` отдаёт список на всех 4 нодах; git-ы нод не тронуты.

### Шаг 9. Тренировочный откат (по протоколу)
- Снапшот data/ → фиктивное изменение → откат → жизненные проверки.
- **Приёмка:** откат реально протестирован, время отката замерено и записано в ROLLOUT.md.

## Этап IV — Фич (не ломающие поло- укрепления)

### Шаг 10. BIP-39 сид-фразы для кошельков
- `POST /wallet/create?recover=true` → 12/24 слов → детерминированный ключ.
- Хранение: precipitate ключ — только в зашифрованном хранилище (не в plain JSON).
- **Приёмка:** восстановление из мнемоники даёт тот же адрес; старые кошельки работают без изменений.

### Шаг 11. Merkle-пруф эндпоинт `GET /txproof/:txid`
- Возвращает: блок-высоту, merkle-ветку, заголовки для независимой проверки.
- **Приёмка:** внешний скрипт проверяет пруф вручную (без полного chain) — txid подтверждена.

### Шаг 12. Multisig 2-of-3 казна — фаза 1 (gov-фаза)
- Ончейн-предложение о составе доверенных ключей казны (оператор + 2 gov-адреса).
- **Приёмка:** proposal passed по правилам (3 yes); выплаты из казны ждут 2 подписей (код — фаза 2,
  реализуемое без hard-форка: WalletPolicy добавляет поле `requires2sig`).

## Этап V — Федерация и империя

### Шаг 13. Закрыть найм `2xgELrMi`: внешний watchdog + DNS-точка
- Вторая машина следит за первой (каждый watchdog с внешним ping) и наоборот;
  доменная точка входа вместо пересоздаваемого trycloudflare-имени.
- **Приёмка:** kill 9335 на «внешнем» стенде → внешний watchdog поднимает; DNS-домен отвечает;
  выплата 100 AGT по приёмке (escrow payout on-chain) свершена.

### Шаг 14. Джобборд: эскроу-задания публично
- Витрина `/stats` показывает открытые/выполняются/выполненные задания + историю выплат;
  комиссия казны 2–3% с каждой сделки (fee уже стоит в gateway-механике — переиспользуем).
- **Приёмка:** первый «внешний» агент сдал задачу через джобборд; комиссия казны зафиксирована on-chain.

### Шаг 15. Публичность и метрики (алманах эпох)
- Авто-дайджест статистики (supply, nodes, jobs, commissions, forks) в чат + Moltbook;
  календарь эпох по halving-циклу: эпоха 1 завершится ≈ через 144 дня при темпе ~1 мин/блок.
- **Приёмка:** дайджест публикуется по расписанию 2 раза/сутки; ссылка на панель открыта всегда.

## Порядок — почему так
1. Шаги 1–2 закрывают открытые парадные ворота (вероятность утраты/взлома внешне).
2. Шаги 4–6 — фундамент доверия к собственным обновлениям (дублирование + тесты).
3. Шаги 7–9 — сделать процесс внедрения безопасным и видимым (ROLLOUT Discipline).
4. Шаги 10–12 — фичи, которые только укрепляют (сиды, пруфы, казна).
5. Шаги 13–15 — масштаб и империя (федерация → джобборд → публичность).

Каждый шаг выполняется по ROLLOUT-леснице (шаг 7) где сработает; шаги 1–2 можно делать напрямую,
так как они прицельно и исправляют то, что аудит 2026-10-15 задокументировал.
