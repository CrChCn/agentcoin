# Внедрение изменений в собственное развёртывание Agentcoin

Состав участников, URL, порты, каталоги и сервисы выбирает владелец развёртывания. Историческая лестница из портов одного компьютера не является архитектурой сети. Используйте `LOCAL_NODE_URL` для своей ноды, `NODE_URL` для своего внешнего входа и `PEER_URL` для выбранного соседа. Loopback относится к компьютеру исполнителя.

## 1. Зафиксировать фактическую конфигурацию и данные

Запишите версию, PID/commandline, сервис или задачу, bind, каталог данных и наблюдаемые tip. Сохраните изменения рабочего дерева и локальные файлы конфигурации. Один каталог данных обслуживает ровно один процесс.

Сделайте консистентную резервную копию своего каталога данных в закрытое хранилище. Не публикуйте кошельки, пароли, issuer key, admin token и VPN-адреса. Наличие копии проверяют до обновления.

## 2. Описать изменение и приёмку

Укажите API/форматы/env, совместимость с историей, исполняемые проверки и план отката. Изменения консенсуса требуют явной согласованной активации. Успешная проверка синтаксиса не заменяет проверку поведения.

## 3. Проверить в изолированной среде

```bash
: "${SANDBOX_PORT:?Choose an unused port on this machine}"
export AGT_DATA_DIR="$PWD/data-testnet"
export AGT_BIND=127.0.0.1
node node.mjs "$SANDBOX_PORT"
```

Тестовый клиент получает `SANDBOX_NODE_URL`, например loopback того же компьютера с выбранным портом. При необходимости используйте копию цепи, но собственные синтетические кошельки. Не направляйте отрицательные тесты на действующие счета или production.

Приёмка: реальные позитивные/негативные сценарии, отказ без изменения чужих средств и санкций, перезапуск и восстановление изолированного экземпляра.

## 4. Обновить одну выбранную канарейку

Канарейка определяется конфигурацией оператора, а не фиксированным номером порта. Останавливайте только подтверждённый процесс этого сервиса; ждите освобождения его порта; запускайте его штатным способом с прежним `AGT_DATA_DIR`. Массовое завершение всех `node.exe` запрещено.

Проверьте `/health`, `/life`, паспорт/кабинет, защиту админ-маршрутов и фактическую работу нужного API. Наблюдайте минимум 10–15 минут. Старый tip и низкая наблюдаемая высота разбираются отдельно от падения процесса.

## 5. Распространять по одному участнику

Владелец каждой ноды сам выбирает выпуск и окно обновления. Сначала согласуйте совместимость и проверенные URL, затем повторяйте приёмку на следующих выбранных участниках. Нет обязательного «главного» компьютера или лестницы портов.

Если используется Windows TS wrapper, перед заменой сохраните собственный bind в `AGT_TS_BIND` либо `data-agtx/ts-bind.txt`. Без него TS не запускается; адрес другого оператора не подставляется. Админ-режим TS остаётся `token`.

## 6. Наблюдать

Фриз после релиза — по согласованному плану (для крупных изменений, например, 6 часов). `/health` пригоден для частого liveness; `/life` и независимые аудиты выполняют реже. Метрики должны показывать отдельные состояния transport, stale, chain-validity и sync, без фиктивных успехов.

## 7. Откатить адресно, если приёмка не пройдена

Сохраните логи, наблюдаемые tip и версию. Верните проверенный выпуск только конкретного сервиса. Данные из резервной копии восстанавливают при подтверждённой необходимости и после остановки единственного писателя. `git reset --hard`, `git clean`, удаление цепи и восстановление чужих кошельков не являются автоматическим способом лечения.

## Историческая проверка отката

В отчёте 2026-10-15 зафиксирована тренировка на отдельной копии `data-rolltest`: искусственная порча файла, восстановление снимка и byte-to-byte MATCH за 300 мс. Это архивное свидетельство; оно не подтверждает текущую доступность любого production-хоста.
