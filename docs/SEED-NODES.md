# SEED-Ноды AGENTCOIN · формат конфигурации (TZ-1.1-FINAL, AC-6.3)

Формат зафиксирован по факту чтения кода: `node.mjs` (merge seeds в `peers.json` на старте)
и `/ws/status → p2p.seed`. Нужно честно хранить в двухъ источниках, оба — только **URL**.

## Формат — URL, не `host:port`

Единственный поддерживаемый формат = полный URL со схемой:

```
http://<host>:<port>     # чаще для локальных/loopback пиров
https://<domain>[:443]   # для публичных пиров через TLS (фаннел/реплика)
```

Правила чтения (как их реально парсит код):
- `AGT_SEED_NODES` — env, список через **запятую**, каждый элемент должен матчить `^https?://`.
  Мусорные элементы (без схемы) молча отбрасываются -> считай их ошибкой конфига и логируй бот.
- `$DATA_DIR/seed-nodes.json` — файл, **JSON-массив строк-URL**.
- Оба источника **mkdir** в один и тот же `peers.json` ноды на старте (конфиг -> seed -> xa sig).
- Ограничения: URL без порта -> порт по схеме (80/443 — стандартные, как в connectClient).

## Примеры

### 1) ENV (одна строка, через запятую)

```bash
AGT_SEED_NODES=http://127.0.0.1:9335,http://127.0.0.1:9341,https://agentcoin.work
```

### 2) Файл `seed-nodes.json` (рядом с data-каталогом ноды)

```json
[
  "http://127.0.0.1:9335",
  "http://127.0.0.1:9341",
  "https://agentcoin.work"
]
```

### 3) Как проверить, что нода приняла seeds

```bash
curl -s http://127.0.0.1:9335/ws/status | node -e \
  "let s='';process.stdin.on('data',d=>s+=d).on('end',()=>{const j=JSON.parse(s);console.log('seed:',j.p2p.seed)})"
# ожидаем: seed = количество чистых URL из env+файла, которые также появились в peers.json
```

или в логе ноды: `[peers] seeds merge: +N (seed config)`.

## Хорошая практика

1. **Seed != операторская породистая нода**: ситуативно всё равно что прописать, после
   первого мерджа адреса живут в `peers.json` (bootstrap merge AGIP-23) — сетевую
   информацию большой долей усложняют, нулю не любят «конфиг».
2. Для локальных песочниц — `http://127.0.0.1:<port>`; для внешних — только HTTPS.
3. НЕ указывать более ~3-5 seeds: первые два садятся outbound-cap
   (`AGT_MAX_OUTBOUND`, default 10); больше seed'ов всё равно не расширяет связность.
4. Мониторинг: `/ws/status`, p2p-блок: `seed`, `peer_count`, `subnetsOk`, `eclipseWarn`.
