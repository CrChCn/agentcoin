# Тестовый расчёт прохода 3 (стенд; TEST-единицы, не AGT mainnet)

## Модель
Прямой перевод по тестовой книге стенда. Оператор расчёта — сам стенд
(тестовая книга `test-balances.json`); отдельного механизма удержания нет,
поэтому слово «эскроу» не используется.

## Кто контролирует средства и на каком основании
Средства — записи тестовой книги; движений ончейн нет. Списание с плательщика
происходит в `send` (после приёмки и созданного обязательства), зачисление
получателю — в `confirm`. До `send` средства не заблокированы и не удержаны —
это честно показано стадиями.

## Момент обязательства
Только `POST /settlements/create` после `orders/accept` (состояние `accepted`).
До приёмки — `409 no_obligation`. Сумма берётся из снимка оффера
(`priceAtomic` в заказе), получатель — provider заказа, сеть/genesis и
назначение (`purpose=assignmentId`) привязаны к платежу (`paymentId=pay-<id>`).

## Отказ, отмена, спор, восстановление
- Отказ: `insufficient_test_funds` (кран `/settlements/faucet`), `bad_state`,
  `foreign_settle` — без побочного эффекта.
- Отмена: только плательщиком и только до отправки (`obligation` → `canceled`).
- Спор: открывается до подтверждения (блокирует `send`); после подтверждения
  фиксируется, но выплату не отменяет (лимит прохода 3, полные споры — проход 4).
- Восстановление: книга и платежи персистентны в `dataDir`; повтор любого шага
  идемпотентен (тот же `paymentId`, однократное списание/зачисление).
- Потеря ответа: повтор `create/send/confirm` возвращает тот же результат
  (replay), `getSettlement` — сверка стадий.

## Стадии
`accepted` → `obligation` → `sent (txid test-tx-…)` → `confirmed` → (`needs_reconcile`
только при сетевом сбое). Детерминированные 4xx-отказы бронь журнала снимают —
повтор разрешён свежими данными; 5xx/сеть — `needs_reconcile` со сверкой.

## Доказательство прохода
`test/agentcoin-ecosphere-d.mjs` — 21/21: заказ → артефакт → приёмка →
обязательство 500 → отправка (A 10000→9500) → подтверждение (B +500) →
единственность при повторах → приватность → рестарт.
