# Форензика «двойника» казны AGT — полный разбор, 2026-10-18

## 1. Кто он «он»

Это **никто**. «Двойник» — не человек, не агент и не кошелёк: это **опечатка адреса**
в обёртке auto-майнера, которую цепь честно отразила как обычные COINBASE-транзакции.

| свойство | значение (снято с живой chain.json, h9291) |
|---|---|
| полный адрес | `AGT11a01a612a422dff68f758eefbd9ab3a991439a` |
| длина | **42 символа** (канонический адрес = **43**: `AGT` + 32 hex(pubHash) + 8 hex(checksum)) |
| отличие от казны | казна `…ff68f7558eefbd9…` → двойник `…ff68f758eefbd9…` (пропущена цифра «5»: читаемо «f7558»→«f758e») |
| поступления | **278 coinbase × 50 AGT = 13 900 AGT**, высоты **h66 … h609** |
| исходящие | **0 транзакций, 0 AGT** за всю жизнь цепи |
| где «живёт» | только в истории блокчейна: 278 записей `COINBASE → двойник` |

  `"node.exe" auto-miner.mjs 9335 AGT11a01a612a422dff68f75*8*eefbd9ab3a991439a 60` (адрес без «5»).
- **Исправлена**: коммит [`fc88c23`](https://github.com/CrChCn/agentcoin/commit/fc88c23b76154ab06fc1bf78f3326686ae7f4482), 14.10.2026 14:43:11 +0200 — адрес майнера поправлен на канонический фонд `AGT11a01a612a422dff68f75*58*eefbd9…`; в комментарии коммита прямо сказано: «Coinbase-typos-f758 заблокировал ~13.6k AGT навсегда — больше не повторяется».
- Окно действия ≈ 9 часов; из ~544 блоков окна 278 намайнены с ошибочным получателем.
- Сокращение адресов (first12/last6) визуально делало оба адреса «одинаковыми» на мониторе — так опечатка и просочилась.

## 3. Почему средствами двойника никто не может распоряжаться

Проверено исчерпывающе на этом хосте:
- 28 data-каталогов, **3917** кошельков в `wallets.json`; **все 3917 приватных ключей
  проверены деривацией** `addressFromPub(privKey→pub)` — **ни один не выводится в адрес
  двойника**; двойника нет ни как созданный кошелёк, ни в каком-либо файле.
- Форматное доказательство: канонический адрес — **всегда 43 символа**. Двойник — 42.
  `addressFromPub` физически не может выдать 42-символьную строку → **не существует
  ключа (ни текущего, ни будущего), который контролирует двойника**.
- Итог: 13 900 AGT учтены сетью (баланс двойника = 13 900), но **потратить их нельзя
  без изменения правил консенсуса** — и никто в мире не может этого сделать тайно.

## 4. Запрет сети создавать двойников (реализовано в ветке CORE-P0)

Активируется тем же порогом `AGT_CORE_P0_HEIGHT` (см. [docs/CORE-P0-ACTIVATION.md](CORE-P0-ACTIVATION.md)):

1. **coinbase_bad_recipient** — награда блока идёт только на канонический адрес
   `AGT + 40 hex`; именно эта проверка отвергла бы ситуацию h66 ещё 14.10.
2. **tx_bad_recipient** — получатель обычной tx тоже канонический; эскроу-open платят
   в `ESCROW_<id>` (свои правила), системные адреса отвергаются отдельной веткой.
3. **bad_recipient (mempool fail-fast)** — в `addTransaction` неканонический получатель
   отклоняется до бан-фильтра: опечатка не запоминается и никого не банит.
4. Историческая совместимость: легаси-элементы старой цепи (`dummy-miner`, `undefined`,
   `AGT_GATEWAY_TEST_V3` и сам двойник) валидируются как раньше; правило действует
   только для высот ≥ порога.

Тесты: `test/core-p0.mjs` T15a/b, T16, T16b (32/32 ALL PASS).

## 5. «Перевести 13 900 на мой кошелёк» — отдельное предложение политики сети (НЕ в PR#4)

> **Статус 2026-10-19:** ранний механизм TWIN-SWEEP **удалён из security PR** по ревизии
> Королера (comment 6270365807 пункт 1): twinSweepSpec допускал канонического чужого from
> через env, а verifyTwinSweepTx проверял подпись «операторского» ключа вместо владельца.
> Это было бы НОВЫМ исключением полномочий, которого аудит не разрешал. Вердикт принят:
> миграция из двух произвольных параметров верификатора не является безопасным механизмом
> консенсуса; политика возврата не входит в правку кода.

1. Механизм ВЫМЕРТ: env-переменные `AGT_TWIN_SWEEP_FROM/TO/AUTH_PUB`, функции
   `twinSweepSpec` / `verifyTwinSweepTx` и все три точки приёма (блок, мемпул,
   usableMempoolTxs) **удалены** из [core.mjs](../core.mjs). Расход средств двойника
   теперь невозможен в консенсусе вообще: подписи владельца у 42-символьного адреса
   не существует (нет ключа — нет подписи — `tx_bad_signature_or_escrow`), системный
   from ≠ COINBASE отвергается `system_spend_forbidden`. Тесты T17/T18 это проверяют.

2. Будущее решение о возврате 13 900 AGT — ОТДЕЛЬНОЕ предложение политики сети:
   с версионированным каноническим digest'ом авторизационных полей, fail-closed
   активационной высотой и общим checkpoint/policy, одобренное оператором и
   координатором в issue #1. До такого решения: история не переписывается,
   средства остаются на неканоническом адресе, «кражи/владельца» не заявляются
   (позиция Королера в 6250846229: «Возможность восстановления — отдельная открытая
   политика сети»).
