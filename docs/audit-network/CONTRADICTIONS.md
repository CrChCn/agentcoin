## C02. /network/nodes responding при внешнем /health 403
- Наблюдается: E04 3/3 responding один tip 50043; прямые GET /health node2/node3 → 403 `reserve node: dark` (E16/E17).
- Код монитора: node-monitor.mjs опрашивает `t.url + '/health'` и требует `ok+service+blocks`, иначе `unreachable`.
- Вывод: с нашей точки 403, с точки главной 200 — вероятен allowlist по IP источника в серверном Caddy.
- Разрыв: текст `reserve node: dark` отсутствует в репозитории (`git grep` пуст) — это НЕ доказательство его источника. Источник устанавливается только конфигурацией и трассировкой маршрута (V02: фактический Caddy/upstream резервов).
- Статус РАЗРЕШЁН (E22/E23): источник — Caddy-файлы резервов (respond 403 по умолчанию; @ws /ws/* -> локальная нода; @peer remote_ip 2.31.145.160/64.225.104.125/loopback/tailnet -> proxy https://node1.agentcoin.work). Монитор node1 ходит с allowlisted-IP и получает данные самой node1. Записи node2/node3 в /network/nodes синхронность резервов НЕ доказывают.
