# wAGT: подтверждения, остановки, роли, сверка (мост AGT ↔ wAGT)

Только тестовые средства. Реализация ворот — `scripts/cycle.mjs`
(`relayMint`, `relayReleaseGate`, `routeHalt`); контракт — `contracts/WAGT.sol`.

## 1. Когда депозит доступен для mint / burn разрешает release

Пороги — env, стенд по умолчанию: `WAGT_MIN_AGT_CONF=2`, `WAGT_MIN_EVM_CONF=2`.

- Mint: lock-tx обязан быть в запечатанном блоке AGT (`/txproof` 200 с высотой)
  И `tip - proofHeight >= WAGT_MIN_AGT_CONF`. До порога — отказ `lock_immature`
  (не очередь, не mint): реорг ещё может унести событие. Неизвестный lock —
  `lock_event_missing`.
- Release: burn обязан быть в канонической цепи EVM (receipt status 1)
  И `evmTip - burnBlock >= WAGT_MIN_EVM_CONF`. До порога — `burn_immature`.
- Проверено на стенде (`npm run cycle`): R0 (missing), R1 (immature→mature
  после добора блоков), главная ветка (burn зрел → release), отчёт
  `cycle-report.json` (поля `minAgtConf/minEvmConf`, все R-флаги true).

## 2. Откат до и после порога (стенд R2)

- Откат ДО порога: событие незрелое — mint/release и так заблокированы
  воротами; последствий нет.
- Откат ПОСЛЕ порога (стенд: `evm_snapshot` → burn → добор → `evm_revert`):
  receipt исчезает → ворота возвращают `burn_event_vanished` и ставят
  `haltRoute(evm2agt)`. Пока halt стоит, НОВЫЕ операции направления
  отклоняются (проверено: повторный release блокирован). Halt затрагивает
  только своё направление (mint-направление остаётся открытым).
- Halt снимается ТОЛЬКО вручную (`operatorResetHalt` с причиной разбора),
  событие пересоздаётся заново (повторный burn), ворота снова требуют порог,
  затем release. Проверено: после сброса release 1 AGT прошёл, инвариант цел.

## 4. Перезапуск и сверка (ресинк)

Реестр релейера сейчас в памяти (`ledger`), второй рубеж — on-chain
`mintedDeposit[depositId]` (повтор отклоняется контрактом `deposit_replayed`).
После перезапуска:

1. Прочитать `BridgeMint`/`BridgeBurn` события и `mintedDeposit` по известным depositId.
2. Незамороженные lock (txproof зрел, mint-события нет) — обработать воротами заново.
3. Отчёт сверки: `reserve (vault баланс AGT) == wAGT totalSupply`; список
   незавершённых (lock без mint, burn без release) с txid обеих цепей.
4. НЕОБЪЯСНЁННОЕ РАСХОЖДЕНИЕ ОСТАНАВЛИВАЕТ НОВЫЕ ВЫДАЧИ: поставить halt
   вручную на оба направления до разбора (аналог `haltRoute`).

Шаблон отчёта: `cycle-report.json` (`contracts`, `agt.lockTx*/releaseTx`,
`evmTx.*`, `amounts`, `checks`) + живой `LIVE-EVIDENCE-sepolia.md`
(для Sepolia: хеши, ссылки на explorer, газ).

## 5. Правила остановки (итог)

- Ворота: незрелое/пропавшее событие → отказ, mint/release нет.
- Откат после порога → halt направления с причиной; новые операции стоят.
- Расхождение резерв/выпуск без объяснения → halt обоих направлений вручную.
- Halt снимается только вручную после разбора; mainnet — только мультисигом.

## 6. Мост v2: пауза, ротация, переживание рестарта (`contracts/WAGTv2.sol`, стенд `npm run cycle:v2` → 23/23)

Роли: owner (смена minter/pauser), pauser (пауза/снятие), minter (только mint).
Пауза блокирует mint И burn; transfer выпущенных ранее балансов работает;
заявка, поданная до паузы, но не исполненная, ждёт снятия и исполняется после.
Снимает паузу только pauser; owner без роли pauser остановить мост не может.
Владение: owner_ назначается при развёртывании (в проде — адрес мультисига; деплоер без owner_ прав не получает, O3); передача — только в два шага (`transferOwnership` + `acceptOwnership`, O5-O8; нулевой адрес и чужой accept отклоняются); старый владелец после передачи без прав (O9, O12). После настройки только назначенный владелец меняет minter/pauser.
Ротация: `setMinter` только owner; старый ключ сразу теряет выпуск (`not_minter`),
новый выпускает; посторонний не меняет minter и не выпускает (`not_owner`/`not_minter`).
Рестарт релейера: журнал намерений и halt — файлы (`ledger.json`, `halt.json`),
а не память. Ресинк после запуска сверяет каждую intent-запись с обеими цепями
(`txproof` AGT + `mintedDeposit` on-chain): mint в блоке, но без записи результата —
повтора НЕТ (`already-minted`, supply не меняется); намерение без mint — исполняется один раз.
Отчёт резерва: `{vault, supply, open[]}`; `vault == supply` и пустой список открытых —
норма. Необъяснённое расхождение останавливает ОБА направления, причина — в halt-журнале;
сброс только вручную после разбора. Учебный пример расхождения на стенде — прямой
перевод из vault без burn (в проде такое движение возможно только ключом хранителя).
Отчёт стенда: `cycle-v2-report.json` (роли, P/R/S/V-флаги, halt-журнал).

## 7. Приёмка к mainnet: оба направления, реорги, резерв с открытыми (`scripts/accept-v2-mainnet.mjs`, стенд `npm run accept:v2` → 27/27)

Дополняет cycle-v2 закрытием пробелов ТЗ. Итоговый SHA `080064ad`, оба стенда
зелёные на нём: `cycle:v2` 23/23 + `accept:v2` 27 проверок. Отчёт: `accept-v2-report.json`
(свидетельства по каждому кейсу: журнал до/после, состояние обеих цепей, txid).

Mint (AGT→wAGT): Ma — сбой после intent, до отправки: ресинк исполняет ровно один раз;
Mb — mint-tx в мемпуле EVM (receipt null, automine выкл): ресинк дожимает её как есть,
второй отправки НЕТ; Mc — tx в блоке, сбой до записи: `already-minted`, supply не меняется;
Md — lock исчез из цепи (`lock_event_vanished`): mint НЕТ, направление остановлено,
сброс только вручную после разбора.

Release (wAGT→AGT): Ea — сбой после intent зрелого burn: ровно одна выплата;
Eb — выплата висит в мемпуле AGT: ресинк подтверждает её как есть, второй выплаты НЕТ;
Ec — выплата в блоке, сбой до записи: повтор НЕ создаётся (баланс не меняется);
Ed — подтверждённый burn стёрт реоргом (`evm_snapshot`/`evm_revert` после порога):
`burn_event_vanished` + halt направления, новые выплаты стоят; сброс вручную,
burn пересоздан, ворота снова требуют порог, выплата проходит;
Ee — выплата не находится ни в цепи, ни в мемпуле (неоднозначный результат):
новой выплаты на тот же burn НЕТ (`release_fate_unknown` + halt), решает оператор.

Инвариант «один депозит — один выпуск, один burn — один возврат» держится
парой рубежей: файловый журнал intent (идемпотентность релейера) + on-chain
`mintedDeposit` (контракт отклоняет повтор `deposit_replayed`).

Резерв с открытыми операциями: `expected.vaultAfterSettle = vault − Σоткрытых выплат −
Σсожжённых-без-выплаты`, `expected.supplyAfterSettle = supply + Σоткрытых mint`;
норма — равенство. Сожжённый-без-выплаты (Ee) — объяснённый излишек vault,
виден в отчёте отдельно (`unreleasedBurns`). Необъяснённое расхождение:
контракт на паузу + halt обоих направлений; возобновляет ТОЛЬКО оператор
после разбора (причина и оба состояния цепей — в `halt.json`): remediation
(докапитализация/списание решением владельца) → ручной сброс halt с причиной →
`unpause` → контрольный mint. На mainnet: пауза — pauser (дежурный мультисиг),
снятие и сброс — только подписью owner-мультисига после разбора.

Контрольный цикл на v2 (стенд F): lock 40 AGT → mint 40 → `addLiquidity(40/400)`
→ lock 5 → mint 5 → продажа 2 wAGT (формула V2 сошлась) → покупка обратно →
сжигание целой части → возврат → `vault == supply`, открытых нет, `x*y=k` держится.
Дробная пыль wAGT (< 1) не сжигается и не возвращается: остаётся у трейдера,
в резерв не попадает (AGT — целочисленный).

## 8. Лимиты выпуска и возврата (ТОЛЬКО релейер)

В контракте WAGTv2 лимитов НЕТ: ABI не содержит лимитных функций (проверено
стендами, cycle-v2 L7 / accept-v2 L7). Все лимиты — ворота релейера
(`gateMint`/`gateRelease` в `cycle-v2.mjs`/`accept-v2-mainnet.mjs`), до обращений
к цепям. Превышение: заявка помечается `needs-review`, направление
останавливается (`mint_limit_exceeded` / `release_limit_exceeded`), сброс —
только вручную после разбора (стенд L5/L6 + сбросы).

Значения стенда: `maxMintPerOp = 40`, `maxReleasePerOp = 10` (целые AGT/wAGT).
Проверено: граница 40/10 — разрешено; 41/11 — отказ; попытка 41 через реальный
путь ресинка — mint НЕТ, supply не изменился; попытка 11 — выплата НЕ создана.
Стартовый выпуск сценария укладывается в лимиты: 40 (граница mint, стенд F),
5 (трейдер), контрольный возврат ≤ 10 (стенд F, проверка ворот).

На mainnet значения лимитов — решением владельца (лист решений, п.5);
техническое место применения то же: только релейер, контракт лимитов не знает.

## 9. Кошельки стендов (кто владеет, кто подписывает, ожидаемый остаток)

EVM-подписанты — встроенные аккаунты hardhat (deployer/minter/pauser/stranger/
trader/lp); AGT-кошельки (`user`, `vault`, `sink`, `oper`) — кошельки локальной
ноды стенда. Тестовые средства; ключи никуда не выносятся.

| Шаг стенда | Токены у | Подписывает | Ожидаемый остаток |

| mint (B/C/D/E/F, accept; P/Q/R/S, cycle) | wAGT получает `trader`/`lp` | `minter` (EVM) | баланс получателя +N wAGT; supply +N |
| Внесение ликвидности (F) | `lp` держит ОБА токена: 40 wAGT + 400 tAGT (проверка перед addLiquidity) | `lp` (EVM, approve + addLiquidity) | пул 40/400; у `lp` — shares |
