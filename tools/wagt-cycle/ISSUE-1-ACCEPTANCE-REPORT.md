## 2. Кто может выпускать wAGT и в каком объёме

Сверка с контрактом (`contracts/WAGTv2.sol`, SHA выше):

- `mint` — только `onlyMinter` + `whenNotPaused` + защита от повтора
  (`mintedDeposit[depositId]`, `deposit_replayed`). **Лимита суммы в контракте НЕТ.**
- `burn` — любой держатель, только `whenNotPaused`; выплата AGT — действие
  оператора вне цепи.
- `owner` — смена minter/pauser, запуск/приём передачи владения (двухшаговая,
  ноль отклоняется); `pauser` — ТОЛЬКО пауза/снятие; деплоер без `owner_`
  прав не получает. Посторонний: `not_owner` / `not_pauser` / `not_minter`.
- Лимиты **40/10 действуют ТОЛЬКО в релейере** (ворота `gateMint`/`gateRelease`;
  границы 40/10 разрешены, 41/11 — отказ + halt + ручной сброс; L5/L6 обоих стендов).

Если авторизованный minter вызывает контракт напрямую, сохраняются: пауза
(pauser останавливает любой mint), защита от повторного `depositId`.
НЕ сохраняются: лимиты 40/10, halt направлений, сверка журнала. То есть
скомпрометированный ключ minter со свежими `depositId` может выпускать
без ограничения суммы, пока pauser не остановит.

Перед mainnet требуют изменения контракта: ончейн-ограничения выпуска
(лимит на операцию и/или потолок supply) — сейчас их неоткуда взять, кроме
политики релейера; плюс рассмотреть мультисиг/таймлок на `setMinter` и
мониторинг `BridgeMint`. Без этого гарантия объёма держится на ключе minter,
ключе pauser и честности релейера.

## 3. Что означает vault=42, supply=41

Разница 1 AGT — это сожжённые без выплаты монеты кейса **Ee**
(стенд `accept:v2`, секция C):

- Операция: трейдер сжёг **1 wAGT** (`burnTx 0x86f7…` в приёмке; в отчёте
  `reserve.final.unreleasedBurns[0] = {amount: 1, state: 'void-reviewed'}`).
- Выплата не найдена ни в цепи AGT, ни в мемпуле → исход неоднозначный:
  `resync-release[Ee]: fate-unknown-halt`, новой выплаты НЕТ, направление
  `evm2agt` остановлено (журнал, строка `Ee: судьба неизвестна`).
- Разбор оператора: «выплата-фантом списана, оператор перевыпустит вручную
  после сверки»; halt снят вручную (`operator-reviewed`). Запись остаётся
  `void-reviewed` — ресинк её пропускает, поэтому повторная выплата
  невозможна даже после рестарта.
- Резервная строка это показывает явно:
  `D резерв с открытыми: vault=6-1(релиз)-1(сожжено без выплаты Ee) == supply=2+2`,
  финал: `vault=42, supply=41`, ожидаемо `41 == 41, ok: true`.
- Возобновить обработку может ТОЛЬКО оператор вручную (`resetHalt` после
  разбора); стенд это фиксирует отдельными проверками на каждый halt.
