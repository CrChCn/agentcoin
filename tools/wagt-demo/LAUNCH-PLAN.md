согласования условий с партнёром (см. `PARTNER-CARD.md`, открытые решения).

## 3. Сверка операций выпуска по сценариям (лимит 40/операция)

| Сценарий | AGT в мост | Операций mint | Раскладка |
|---|---|---|---|
| A · Пилот | 40 | 1 | 1×40 |
| B · Рабочий | 283 | 8 | 7×40 + 3 |
| C · Минимум в обе стороны | 289 | 8 | 7×40 + 9 |

Периодов квоты не требуется (их нет в дизайне). Каждая операция — отдельный
вызов `mint` ключом minter; сброс halt после превышения — только вручную
оператором после разбора.

## 4. Порядок запуска

1. Фикс открытых решений 1–6 из карточки партнёру (цена, глубина, газ,
   Safe, доли/выход, лимиты mainnet + назначение ключей
   owner/minter/pauser; деплоер без `owner_` прав не получает).
2. Деплой WAGTv2 в mainnet (owner — согласованный адрес/мультисиг).
3. Деплой Safe 2-of-2 (владельцы: проект + партнёр).
4. Резерв AGT (цепь AGT) → выпуски wAGT по §3 → оба актива на Safe.
5. Safe выполняет approve + addLiquidity (создаёт пару wAGT/WETH).
6. Три контрольные операции подряд (см. §5).

## 5. Три контрольные операции (конец плана, все — фактом в цепи)

1. **Покупка wAGT**: оператор покупает ровно 2 wAGT за WETH по цене пула
   (ожидание по варианту — из таблицы карточки; допуск 1% при C).
2. **Продажа wAGT**: оператор продаёт 2 wAGT (ожидание — из таблицы).
3. **Возврат части wAGT в родной AGT**: держатель сжигает `burn` (сумма ≤
   10 wAGT — в лимите релейера), релейер выплачивает AGT; сверка
   vault == supply с учётом возврата.
